# Git — краткая шпаргалка

[[Лекции по введению в ТП|← К списку лекций]]

## Что такое Git

**Git** — распределённая система контроля версий (VCS).

Нужен для:

- истории изменений;
    
- отката;
    
- совместной работы;
    
- отслеживания авторства.
    

---

## Состояния файлов

```text
untracked → staged → committed
              ↑
           modified
```

- `untracked` — Git ещё не отслеживает файл.
    
- `modified` — файл изменён после последнего коммита.
    
- `staged` — изменения выбраны для следующего коммита.
    
- `committed` — изменения записаны в историю.
    

```bash
git add file
```

→ добавить изменения в `staged`.

```bash
git commit -m "message"
```

→ создать коммит.

---

## Commit

Коммит — зафиксированный слепок состояния репозитория.

Содержит:

- изменения;
    
- ссылку на предыдущий коммит;
    
- автора;
    
- сообщение;
    
- дату и время.
    

---

## Ветки

Ветка — указатель на последний коммит своей линии истории.

```text
A → B → C   main
     \
      D → E   feature
```

```bash
git switch --create feature
```

создать ветку и перейти в неё.

```bash
git switch main
```

переключиться.

```bash
git branch --all
```

показать ветки.

```bash
git branch --delete feature
```

удалить ветку.

---

## Удалённый репозиторий

`origin` — стандартное имя удалённого репозитория после `git clone`.

```text
main        — локальная ветка
origin/main — удалённая ветка
```

```bash
git push --set-upstream origin feature
```

отправить локальную ветку `feature` в `origin` и связать их.

---

## Merge

Объединяет истории двух веток.

```bash
git merge feature
```

Вливает `feature` в текущую ветку.

История ветвления сохраняется.

---

## Rebase

Переприменяет коммиты поверх другой ветки.

```text
было:
A → B → C
     \
      D → E

после rebase:
A → B → C → D' → E'
```

```bash
git rebase main
```

Коммиты пересоздаются, история становится линейной.

Перед rebase можно сделать резервную ветку:

```bash
git branch backup-br
```

Идея:

```text
ветка = указатель на коммит
```

---

## Clone и Fork

```bash
git clone <url>
```

`clone` — скачать репозиторий себе локально.

`fork` — создать свою копию чужого репозитория на GitHub.

Обычно:

```text
origin   — твой репозиторий / форк
upstream — оригинальный репозиторий
```

---

## Pull Request

Pull Request — запрос на включение изменений из одной ветки в другую, обычно в `main`.

```text
feature
  ↓
Pull Request
  ↓
review
  ↓
merge / rebase / squash
```

---

## Конфликты

Возникают, если разные ветки несовместимо изменили одно и то же место.

```text
<<<<<<< HEAD
вариант 1
=======
вариант 2
>>>>>>> branch
```

Нужно вручную выбрать нужный код.

## Git и GitHub

```text
Git = система контроля версий
GitHub = сервис для хранения Git-репозиториев и командной работы
```

## Полезные команды

```bash
git add .
```

добавить почти все текущие изменения в `staged`.

```bash
git commit --amend
```

исправить последний коммит.

```bash
git stash
```

временно спрятать незакоммиченные изменения.

```bash
git stash apply
```

вернуть их.

```bash
git add --patch
```

выбрать отдельные куски изменений.

```bash
git log --graph --oneline --all
```

показать историю как граф.

```bash
git reset HEAD^
```

убрать последний коммит, но сохранить изменения.

```bash
git reset HEAD^ --hard
```

убрать последний коммит вместе с изменениями.

---

## Главное

```text
git add     → подготовить изменения
git commit  → записать их в историю
branch      → отдельная линия работы
merge       → соединить истории
rebase      → переписать историю линейно
push        → отправить изменения на remote
pull        → получить изменения с remote
```
