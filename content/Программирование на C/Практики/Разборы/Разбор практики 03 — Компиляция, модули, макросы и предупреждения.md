## Что полезно вынести из практики

| Приём | Когда пригодится |
|---|---|
| `gcc --save-temps` | Понять, во что превращается `.c` на каждой стадии сборки |
| `gcc -E` | Посмотреть раскрытие макросов и `#include` |
| `objdump -d`, `objdump -s -j .rodata` | Найти машинные инструкции и константные данные |
| `nm` (`T`, `t`, `U`) | Проверить, какие функции определены в объектном файле и какие нужны извне |
| `static inline` | Определять небольшие вспомогательные функции прямо в заголовках |
| `-I каталог` | Подключать заголовки из другой директории |
| Скобки в макросах | Избежать ошибок текстовой подстановки и приоритета операторов |
| `-Wall -Wextra -Wpedantic -Werror` | Находить подозрительный код ещё при сборке |

## Задача 1. Где живут строки, числа и функции

**Из презентации (слайды 1–4):** программа выводит `Hello world! Today is September 25.` с помощью `%s` и `%d`. Требуется сохранить промежуточные файлы, найти строку и число в объектном файле, прочитать вывод `nm`.

<details>
<summary><strong>Файл task01.c — полный воспроизводимый пример</strong></summary>

```c
#include <stdio.h>

int main(void) {
    const char *month = "September";
    int day = 25;
    printf("Hello world! Today is %s %d.\n", month, day);
    return 0;
}
```

**Реконструкция**, а не оригинальный файл со слайда. Способ хранения `day` зависит от сборки: компилятор не обязан кодировать `25` непосредственно в инструкции.

</details>

### Полезные команды

```bash
gcc --save-temps task01.c -o task01
# task01.i — после препроцессора
# task01.s — ассемблер
# task01.o — объектный файл
# task01   — исполняемый файл

objdump -d task01.o             # машинные инструкции в читаемом виде
objdump -s -j .rodata task01.o # байты константных данных
nm task01.o                     # символы объектного файла
```

<details>
<summary><strong>Где находятся September и 25? — разбор</strong></summary>

- В примере из презентации строка `September` и строка формата `printf` лежат в **`.rodata`**.
- Число `25` в показанном дизассемблировании — непосредственный операнд инструкции `mov $0x19, ...` (`0x19 = 25`).
- Константа **не обязана** находиться в `.rodata`: компилятор может использовать литерал непосредственно в машинной команде.

| Секция | Типичное содержимое |
|---|---|
| `.text` | Инструкции программы |
| `.rodata` | Строковые литералы и константные данные |
| `.data` | Инициализированные статические/глобальные переменные |
| `.bss` | Неинициализированные или нулевые статические/глобальные переменные |

</details>

<details>
<summary><strong>Как читать nm: T, t и U</strong></summary>

В презентации для `task01.o` показано:

```text
T main
U printf
```

- `T` — глобальный символ определён в `.text`.
- `t` — локальный символ в `.text` (например, `static`-функция).
- `U` — определение символа отсутствует **в данном** объектном файле; связывание происходит позже.

`#include <stdio.h>` даёт **объявление** `printf`; реализация функции находится в библиотеке C. `U` в объектном файле — нормальная ситуация, а не обязательно ошибка.

</details>

**Практический вывод:** `objdump` помогает увидеть *что сгенерировал компилятор*, а `nm` — *какие имена можно связать между объектными файлами*.

## Задача 2. Несколько файлов: заголовки, static inline и -I

**Из презентации (слайды 5–9):** `main.c` вызывает `distance`, `distance.c` её определяет, `distance.h` объявляет. В исходном задании забыто подключение заголовка; `abs` ошибочна; `argc` не проверяется.

### Пример с ошибками

<details>
<summary><strong>distance.h — реконструкция</strong></summary>

```c
#ifndef DISTANCE_H
#define DISTANCE_H

static inline int abs(int x) {
    return x < 0 ? x : -x; // специально неверно
}

int distance(int a, int b);

#endif
```

Использование имени `abs` в собственном заголовке может конфликтовать со стандартной `abs` из `<stdlib.h>`, если подключить их вместе в одном файле. В исправленном примере используется имя `local_abs`.

</details>

<details>
<summary><strong>distance.c — реконструкция</strong></summary>

```c
#include "distance.h"

int distance(int a, int b) {
    return abs(b - a);
}
```

При аргументах `10` и `3` ошибочная `abs(-7)` возвращает `-7`, как в ответе презентации. Оригинальное тело `distance` не показано.

</details>

<details>
<summary><strong>main.c — реконструкция с ошибками</strong></summary>

```c
#include <stdio.h>
#include <stdlib.h>

// Пропущен #include "distance.h"
int main(int argc, char *argv[]) {
    int a = atoi(argv[1]);
    int b = atoi(argv[2]);
    printf("%d\n", distance(a, b));
    return 0;
}
```

Ошибки: `distance` не объявлена; обращение к `argv[1]` и `argv[2]` без проверки `argc` может вызвать **undefined behavior**.

</details>

### Что здесь действительно стоит запомнить

**1. Компиляция по файлам.** `gcc -c main.c` не ищет объявление `distance` в соседнем `distance.c`. Для вызова нужно объявление (`#include "distance.h"`), а при линковке — объектный файл с реализацией.

```bash
gcc -c main.c -o main.o
gcc -c distance.c -o distance.o
gcc main.o distance.o -o prog
```

**2. `static inline` — два независимых свойства.**

```c
static inline int local_abs(int x) {
    return x < 0 ? -x : x;
}
```

- `static`: имя функции имеет **внутреннее связывание** в каждой единице трансляции.
- `inline`: допускает замену вызова телом функции; **не гарантирует** её.
- Поэтому `static inline` удобно для коротких определений в `.h`, включаемых в несколько `.c`.

**3. Символы в объектном файле.** На слайде `nm distance.o` показывает `t abs` (локальная `static`) и `T distance` (глобальная). С оптимизацией встраиваемая функция может вообще исчезнуть из отдельной таблицы функций.

**4. Проверка аргументов должна предшествовать чтению `argv`.** Отсутствие аргументов не обязано давать именно segmentation fault: это **UB**. На слайде показан конкретный запуск, закончившийся segmentation fault.

<details>
<summary><strong>Исправленная программа по файлам</strong></summary>

**distance.h**

```c
#ifndef DISTANCE_H
#define DISTANCE_H

static inline int local_abs(int x) {
    return x < 0 ? -x : x;
}

int distance(int a, int b);

#endif
```

**distance.c**

```c
#include "distance.h"

int distance(int a, int b) {
    return local_abs(b - a);
}
```

**main.c**

```c
#include <stdio.h>
#include <stdlib.h>
#include "distance.h"

int main(int argc, char *argv[]) {
    if (argc != 3) {
        fprintf(stderr, "Usage: %s <a> <b>\n", argv[0]);
        return 2;
    }

    int a = atoi(argv[1]);
    int b = atoi(argv[2]);
    printf("%d\n", distance(a, b));
    return 0;
}
```

```bash
gcc -std=c99 -Wall -Wextra main.c distance.c -o prog
./prog 10 3  # 7
```

> Это **упрощённое исправление** именно ошибок со слайдов. `atoi` не проверяет корректность текста аргументов, а вычитание/модуль могут переполнить `int` на крайних значениях. Для пользовательского ввода лучше `strtol` с проверкой диапазона.

</details>

### Файлы в отдельной папке

```text
project/
├── main.c
└── dist/
    ├── distance.c
    └── distance.h
```

Два способа подключить заголовок:

<details>
<summary><strong>Способ A — параметр компилятора -I</strong></summary>

В `main.c`:

```c
#include "distance.h"
```

Сборка:

```bash
gcc -std=c99 -I dist main.c dist/distance.c -o prog
```

`-I dist` добавляет каталог **поиска заголовков**. Сам файл `distance.c` всё равно нужно передать компилятору отдельно.

</details>

<details>
<summary><strong>Способ B — путь в #include</strong></summary>

В `main.c`:

```c
#include "dist/distance.h"
```

Сборка:

```bash
gcc -std=c99 main.c dist/distance.c -o prog
```

`distance.c`, находящийся рядом со своим `distance.h`, может использовать `#include "distance.h"` без дополнительного `-I dist`.

</details>

## Задача 3. Почему макросы опаснее функций

**Из презентации (слайды 10–13):** два макроса вычисляют «модуль», но дают разные результаты из-за скобок и приоритета операторов.

<details>
<summary><strong>main.c — полный пример</strong></summary>

```c
#include <stdio.h>

#define abs1(x) x > 0 ? x : -x
#define abs2(x) ((x) > 0 ? (x) : (-x))

int main(void) {
    int x = 7;
    int y = -8;

    int a1 = x + abs1(y);
    int a2 = x + abs2(y);
    printf("a1 = %d, a2 = %d\n", a1, a2);
    return 0;
}
```

Сами определения макросов и выражения `a1`, `a2` взяты из слайда; обёртка `main` восстановлена.

</details>

**Приём: посмотреть реальную подстановку.**

```bash
gcc -E main.c | grep 'int a[12] ='
```

В презентации:

```c
int a1 = x + y > 0 ? y : -y;
int a2 = x + ((y) > 0 ? (y) : (-y));
```

<details>
<summary><strong>Почему a1 = 8, а a2 = 15?</strong></summary>

`?:` имеет меньший приоритет, чем `+` и `>`.

```c
// abs1: условие охватывает x + y
(x + y > 0) ? y : -y
// (7 - 8 > 0) ? -8 : 8  →  8

// abs2: сначала вычисляется условный оператор в скобках
x + ((y) > 0 ? (y) : (-y))
// 7 + 8  →  15
```

</details>

<details>
<summary><strong>Вторая ошибка: отрицание выражения a - b</strong></summary>

```c
#define abs2(x) ((x) > 0 ? (x) : (-x))
```

Подстановка `abs2(a - b)` даёт:

```c
((a - b) > 0 ? (a - b) : (-a - b))
```

Но нужно `-(a - b)`, поэтому корректнее:

```c
#define ABS(x) ((x) > 0 ? (x) : -(x))
```

Даже этот вариант **опасен для аргументов с побочными эффектами**: `ABS(i++)` может увеличивать `i` больше одного раза. В обычной программе лучше отдельная функция, если не требуется именно макрос.

</details>

**Три правила:** скобки вокруг тела макроса, скобки вокруг каждого использования аргумента и скобки при отрицании сложного аргумента. Макрос — текстовая подстановка, а не безопасный вызов функции.

## Задача 4. Диагностика GCC — какие предупреждения действительно помогают

**Из презентации (слайды 14–18):** сравнены `-Wall`, `-Wextra`, `-Wpedantic` и `-Werror` на трёх коротких программах.

| Флаг | Для чего нужен |
|---|---|
| `-Wall` | Частые ошибки и подозрительные конструкции |
| `-Wextra` | Дополнительные проверки, в том числе сравнение signed/unsigned |
| `-Wpedantic` | Диагностика расширений вне выбранного стандарта ISO C |
| `-Werror` | Считать сработавшие предупреждения ошибками сборки |

<details>
<summary><strong>Файл warn.c — присваивание в условии</strong></summary>

```c
#include <stdio.h>

int main(void) {
    int a, b;
    int d; // не используется

    scanf("%d %d", &a, &b);
    if (a = b) { // присваивание, а не сравнение
        printf("%d\n", a + b);
    }
    return 0;
}
```

```bash
gcc -Wall warn.c -o warn
printf '3 4\n' | ./warn   # 8
```

`a = b` присваивает `4` в `a`; условие истинно и печатается `4 + 4`. `-Wall` предупреждает о присваивании в условии и неиспользуемой `d`.

```bash
gcc -Wall -Werror warn.c -o warn
# Предупреждения становятся ошибками; успешной сборки нет.
```

</details>

<details>
<summary><strong>Файл wextra.c — сравнение signed и unsigned</strong></summary>

```c
#include <stdio.h>

int main(void) {
    int a = -1;
    unsigned int b = 1;

    if (a > b) {
        printf("-1 is bigger then 1\n");
    }
    return 0;
}
```

```bash
gcc -Wall wextra.c -o wextra
gcc -Wall -Wextra wextra.c -o wextra
```

В примере из презентации именно `-Wextra` добавляет предупреждение о сравнении знакового и беззнакового значения. `int -1` при сравнении с `unsigned int 1` преобразуется к беззнаковому типу; для обычного 32-битного `unsigned int` это `4294967295`.

Программа выводит неожиданное сообщение о том, что `-1` больше `1`.

</details>

<details>
<summary><strong>Файл wpedantic.c — нестандартный массив</strong></summary>

```c
int main(void) {
    int a[0];
    return 0;
}
```

```bash
gcc -Wall wpedantic.c     # предупреждение о неиспользуемой a
gcc -Wextra wpedantic.c   # в примере нет предупреждений
gcc -Wpedantic wpedantic.c # ISO C forbids zero-size array
```

Массив нулевой длины — расширение GCC, не стандартный C. Для привязки к нужному стандарту полезно добавить `-std=c99`.

</details>

### Практичная команда для своих проектов

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic main.c -o prog
```

Если требуется принципиально чистая сборка:

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic -Werror main.c -o prog
```

`-Werror` **не включает предупреждения сам**: он лишь повышает тяжесть уже включённых диагностик.

## Краткая памятка: что применять на практике

- **Непонятно, как раскрылся макрос?** `gcc -E`.
- **Нужно увидеть машинные инструкции?** `objdump -d файл.o`.
- **Нужно найти строковый литерал?** `objdump -s -j .rodata файл.o`.
- **Непонятно, кто определяет функцию?** `nm файл.o`; сравнить `T`, `t`, `U`.
- **Функция определена в другом `.c`, но компилятор её не видит?** Подключить заголовок с объявлением.
- **Заголовок лежит в другой папке?** `-I каталог` или путь в `#include`.
- **Короткая функция нужна в нескольких `.c`?** Рассмотреть `static inline` в `.h`.
- **Макрос ведёт себя странно?** Проверить раскрытие, скобки и повторные вычисления аргумента.
- **Неожиданное сравнение отрицательного и положительного?** Проверить `signed`/`unsigned`.
- **Хотелось бы поймать больше ошибок до запуска?** Включить `-Wall -Wextra -Wpedantic`.
