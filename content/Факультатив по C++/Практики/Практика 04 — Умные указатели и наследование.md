# Практика 04 — Умные указатели и наследование

[[Практики по C++|← К списку практик]]

Материал занятия по лекции 11.

## 1. Временные объекты

В C++ важно учитывать **время жизни объектов**, особенно если у класса есть нетривиальные конструкторы и деструкторы.

```cpp
max(2, 3);
```

`2` и `3` — временные объекты. Они создаются для вычисления выражения и живут до конца полного выражения. Возвращаемое значение функции также может быть временным объектом.

Для классов:

```cpp
max(
    BigInt("123"),
    BigInt("456")
);
```

создаются временные объекты `BigInt`, поэтому вызываются их конструкторы и деструкторы.

## 2. Параметры по умолчанию

```cpp
void startServer(
    const char* name,
    int port = 8080,
    const char* host = "0.0.0.0"
);
```

Можно писать:

```cpp
startServer("minecraft", 25565, "127.0.0.1");
startServer("postgresql", 5432);
startServer("ping");
```

В последнем случае компилятор подставит:

```cpp
startServer("ping", 8080, "0.0.0.0");
```

Параметры со значениями по умолчанию должны идти **последними**.

```cpp
void f(int a, int b = 10); // OK
```

Значения по умолчанию обычно указываются в объявлении функции в `.h`, потому что компилятор подставляет их непосредственно в место вызова.

## 3. `new` / `delete` с объектами

`malloc` только выделяет сырые байты памяти и **не вызывает конструктор**.

`free` освобождает память, но **не вызывает деструктор**.

```cpp
Server* server = new Server(5432);
```

`new`:
1. выделяет память;
2. вызывает конструктор `Server(5432)`.

```cpp
delete server;
```

`delete`:
1. вызывает деструктор;
2. освобождает память.

Если указатель исчезнет без `delete`:

```cpp
void f() {
    Server* s = new Server(1234);
}
```

сам `s` уничтожится, но объект в куче останется → **утечка памяти**.

---

## 4. Placement new

Placement new позволяет создать объект **в уже выделенной памяти**.

```cpp
Server* server = static_cast<Server*>(malloc(sizeof(Server)));
new (server) Server(5432);
```

Placement new не выделяет память, а только вызывает конструктор по указанному адресу.

Уничтожение:

```cpp
server->~Server();
free(server);
```

После `malloc + placement new` нельзя использовать обычный `delete`.

Placement new обычно нужен при реализации структур данных вроде `std::vector`.

---

## 5. `new[]` / `delete[]` с объектами

```cpp
BigInt* arr = new BigInt[100];
```

`new[]` вызывает конструктор по умолчанию для каждого элемента массива.

```cpp
delete[] arr;
```

`delete[]` вызывает деструктор каждого объекта.

Если у класса нет конструктора без аргументов, `new BigInt[100]` не скомпилируется.

# Умные указатели

## 6. Идея smart pointer

Обычный указатель:

```cpp
Object* p = new Object(...);
p->doSomething();
delete p;
```

Требует вручную помнить про `delete`.

Умный указатель — объект-обёртка, который хранит указатель и автоматически удаляет объект в своём деструкторе.

---

## 7. `scoped_ptr`

Упрощённая структура:

```cpp
class scoped_ptr {
private:
    Object* ptr_;

public:
    scoped_ptr(Object* ptr);
    ~scoped_ptr();

    Object* get() const;
    Object& operator*() const;
    Object* operator->() const;
    explicit operator bool() const;
};
```

Деструктор:

```cpp
scoped_ptr::~scoped_ptr() {
    delete ptr_;
}
```

Когда `scoped_ptr` выходит из scope, объект автоматически удаляется.

### Почему нельзя копировать

Если разрешить:

```cpp
scoped_ptr a(...);
scoped_ptr b = a;
```

оба объекта будут хранить один адрес.

При уничтожении получится два `delete` одного объекта → `double free`.

Поэтому copy constructor и `operator=` запрещаются.

---

## 8. Виды умных указателей

### `scoped_ptr`

- нельзя копировать;
- нельзя передавать владение;
- один владелец.

### `unique_ptr`

- нельзя копировать;
- можно перемещать;
- можно передавать владение;
- в каждый момент владелец один.

### `shared_ptr`

- можно копировать;
- несколько указателей могут владеть одним объектом.

---

## 9. `shared_ptr`

Основная идея — **счётчик владельцев**.

```text
создали shared_ptr -> refcount = 1
скопировали        -> refcount = 2
копия уничтожилась -> refcount = 1
последний исчез    -> refcount = 0
```

При `refcount == 0` удаляется сам объект.

Счётчик должен быть **общим для всех копий**.

### Циклические ссылки

```text
A --shared_ptr--> B
B --shared_ptr--> A
```

Объекты удерживают друг друга, поэтому счётчики не доходят до нуля.

Для разрыва таких циклов используется `weak_ptr`, который не увеличивает счётчик владения.

# Наследование

## 10. Композиция и наследование

### Композиция

Один объект хранится как поле другого:

```cpp
class A {
    B b;
};
```

### Наследование

```cpp
class ColoredButton : public Button {
    ...
};
```

`Button` — базовый класс.

`ColoredButton` — производный класс / наследник.

---

## 11. Конструктор базового класса

При создании наследника сначала должна быть создана базовая часть.

```cpp
ColoredButton(const char* caption, Color color)
    : Button(caption),
      color_(color)
{}
```

`Button(caption)` — вызов конструктора базового класса.

Если явно ничего не указать, компилятор попытается вызвать `Button()`.

Если такого конструктора нет → ошибка компиляции.

При уничтожении порядок обратный: сначала наследник, потом базовый класс.

---

## 12. Приведение наследника к базовому типу

При `public` наследовании:

```cpp
ColoredButton* c = new ColoredButton(...);
Button* b = c;
```

работает автоматически.

Объект `ColoredButton` содержит внутри базовую часть `Button`.

Поэтому можно хранить разные классы в одном массиве:

```cpp
Button* buttons[3];

buttons[0] = new Button(...);
buttons[1] = new Button(...);
buttons[2] = new ColoredButton(...);
```

# Виртуальные методы

## 13. `virtual`

Без `virtual`:

```cpp
Button* b = new ColoredButton(...);
b->draw();
```

будет вызван `Button::draw()`, потому что тип указателя — `Button*`.

Если:

```cpp
virtual void draw();
```

то C++ смотрит на **реальный тип объекта**.

```cpp
Button* b = new ColoredButton(...);
b->draw();
```

вызовет `ColoredButton::draw()`.

Коротко:

```text
обычный метод -> выбор по типу указателя
virtual       -> выбор по реальному типу объекта
```

---

## 14. Виртуальный деструктор

Проблема:

```cpp
Button* b = new ColoredButton(...);
delete b;
```

Если деструктор `Button` обычный, правильный деструктор `ColoredButton` может не быть вызван.

Поэтому:

```cpp
class Button {
public:
    virtual ~Button();
};
```

Теперь при `delete` по `Button*` вызывается деструктор реального объекта, а затем деструктор базового класса.

> Если в классе есть виртуальные методы, деструктор обычно тоже должен быть `virtual`.

Если деструктор базового класса виртуальный, деструкторы наследников автоматически тоже виртуальные.

# Уровни доступа

## 15. `public`, `protected`, `private`

```text
public    -> доступен всем
protected -> доступен классу и его наследникам
private   -> доступен только самому классу
```

`protected` позволяет наследнику использовать детали реализации базового класса, не открывая их внешнему коду.

Иногда вместо `protected` поля лучше оставить поле `private` и дать метод доступа, например `getCaption()`.

---

## 16. Виды наследования

### `public`

```cpp
class B : public A {};
```

```text
public A    -> public B
protected A -> protected B
```

Это отношение «`B` является `A`».

### `protected`

```cpp
class B : protected A {};
```

`public` члены базового класса становятся `protected`.

### `private`

```cpp
class B : private A {};
```

Все неприватные члены базового класса становятся `private`.

При `protected/private` наследовании внешний код не может обычным образом сделать `Derived* -> Base*`.

Не-public наследование используется редко; часто вместо него лучше композиция.

---

# `class` и `struct`

В C++ они почти одинаковые: оба могут иметь методы, конструкторы, деструкторы, наследование, `virtual` и уровни доступа.

Отличия по умолчанию:

| | `struct` | `class` |
|---|---|---|
| доступ | `public` | `private` |
| наследование | `public` | `private` |

```cpp
struct A : B {
    Object x;
};
```

эквивалентно:

```cpp
struct A : public B {
public:
    Object x;
};
```

А:

```cpp
class A : B {
    Object x;
};
```

эквивалентно:

```cpp
class A : private B {
private:
    Object x;
};
```

По стилю:

```text
struct -> простые структуры данных
class  -> объекты со сложной логикой
```

Это соглашение, а не ограничение языка.
