# Практика 07 — Наследование, композиция и полиморфизм

[[Практики по C++|← К списку практик]]

Темы занятия: порядок конструирования и уничтожения при наследовании, композиция, `IS-A` / `HAS-A`, виртуальные функции, object slicing, абстрактные классы и `std::unique_ptr`.

## 1. Создание наследника

При создании объекта производного класса сначала создаётся базовая часть, затем поля наследника в порядке объявления и только потом выполняется тело конструктора наследника.

```cpp
class Person {
public:
    Person(const std::string& name, int age)
        : name_(name), age_(age) {}
protected:
    std::string name_;
    int age_;
};

class Student : public Person {
public:
    Student(const std::string& name, int age,
            const std::string& university)
        : Person(name, age), university_(university) {}
private:
    std::string university_;
};
```

`Person(name, age)` инициализирует базовую часть **того же** объекта. Если его не написать, компилятор попробует вызвать доступный `Person()`. Когда конструктора без аргументов нет, это будет ошибкой компиляции.

При уничтожении порядок обратный: тело деструктора наследника, его поля, затем базовая часть.

## 2. Композиция и порядок полей

**HAS-A** означает, что объект содержит другой объект как поле:

```cpp
class Person {
private:
    std::string name_;
    Address addr_;
    Contact contact_;

public:
    Person(const std::string& name, const std::string& city,
           const std::string& street, int number,
           const std::string& phone, const std::string& email)
        : name_(name), addr_(city, street, number), contact_(phone, email) {}
};
```

`addr_` и `contact_` — полноценные объекты внутри `Person`; их конструкторы запускаются до тела конструктора `Person`.

![[CPP_practice07_assets/composition.svg]]

Важно: поля инициализируются в **порядке объявления в классе**, а не в порядке списка после `:`. Если у поля нет конструктора по умолчанию, его нужно явно инициализировать.

| Связь | Смысл | Реализация | Пример |
|---|---|---|---|
| **IS-A** | «является разновидностью» | `public`-наследование | `Car : public Vehicle` |
| **HAS-A** | «имеет» | поле-объект | `Engine engine_` в `Car` |

Поле-объект копируется при передаче значения в конструктор: у `Car` и исходного `Engine` будут независимые объекты.

## 3. Виртуальный деструктор

```cpp
class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    ~Derived() override { /* освобождение ресурсов */ }
};

Base* p = new Derived();
delete p; // Derived::~Derived(), затем Base::~Base()
```

Если удалять `Derived` через `Base*`, деструктор `Base` должен быть виртуальным. Без него это undefined behavior. `= default` просит сгенерировать стандартную реализацию; это не то же самое, что `= delete`.

## 4. `virtual`, `override` и dispatch

```cpp
class Base {
public:
    virtual void f() {}
    void g() {}
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void f() override {}
    void g() {} // не переопределение: Base::g не virtual
};

Base* p = new Derived();
p->f(); // Derived::f — dynamic dispatch
p->g(); // Base::g — static dispatch
delete p;
```

- Виртуальный метод, вызванный через `Base*` или `Base&`, выбирается по реальному типу объекта.
- Для невиртуального метода выбор идёт по статическому типу выражения.
- `override` проверяет переопределение виртуального метода и защищает от опечаток.
- `Base::Do()` — явный вызов реализации базового класса; виртуальный выбор для него не выполняется.

## 5. Object slicing

```cpp
Derived d;
Base b = d; // копируется только базовая часть
b.f();     // Base::f(), даже если f virtual

Base& ref = d;
ref.f();   // Derived::f(), если f virtual

Base* ptr = &d;
ptr->f(); // Derived::f()
```

**Object slicing** — потеря производной части при копировании объекта наследника в объект базового типа по значению. Указатель или ссылка сохраняют настоящий объект и позволяют динамический полиморфизм; `new` для этого не требуется.

## 6. Абстрактный интерфейс и `unique_ptr`

```cpp
class Shape {
public:
    virtual ~Shape() = default;
    virtual double Area() const = 0;
    virtual double Perimeter() const = 0;
    virtual std::string Name() const = 0;
};

std::vector<std::unique_ptr<Shape>> shapes;
shapes.push_back(std::make_unique<Rectangle>(3.0, 4.0));
shapes.push_back(std::make_unique<Circle>(1.0));
```

`= 0` объявляет чисто виртуальную функцию. `Shape` нельзя создать напрямую, а конкретный наследник обязан реализовать все такие методы.

`std::unique_ptr<Shape>` владеет объектом и автоматически его удаляет. В векторе можно хранить указатели одного базового типа на объекты разных наследников. `unique_ptr` нельзя копировать, поэтому в цикле используют `const auto&`.

## 7. Виртуальные вызовы в конструкторе и деструкторе

```cpp
class Base {
public:
    Base() { Init(); }             // Base::Init()
    virtual ~Base() { Cleanup(); } // Base::Cleanup()
    virtual void Init() {}
    virtual void Cleanup() {}
};

class Derived : public Base {
public:
    Derived() { Init(); }          // Derived::Init()
    ~Derived() override { Cleanup(); } // Derived::Cleanup()
    void Init() override {}
    void Cleanup() override {}
};
```

В конструкторе или деструкторе виртуальный вызов не переходит в более производный класс, чем тот, чья часть объекта сейчас создаётся или уничтожается. В `Base()` производная часть ещё не готова, а в `~Base()` уже уничтожена.

## 8. Дополнительно

### Google C++ Style Guide

Это соглашения по стилю, а не требования языка: классы — `PascalCase`, переменные — `snake_case`, поля — `snake_case_`, константы — `kPascalCase`. В учебном проекте приоритет имеет стиль преподавателя и проекта.

### Boilerplate

Повторяющийся инфраструктурный код: include guards, объявления специальных методов, структура `.h/.cpp`. Стандартные контейнеры, например `std::vector<double>`, часто позволяют сократить его по сравнению с ручным владением `double*`.

### UML

Диаграмма классов показывает типы, поля, методы, наследование и композицию. В обозначениях: `+` — `public`, `-` — `private`, `#` — `protected`; пустой треугольник означает наследование, закрашенный ромб со стороны целого — композицию. Диаграмма объектов показывает конкретные экземпляры и их значения в момент времени.

## Итоговая шпаргалка

| Ситуация | Правило |
|---|---|
| Создание `Derived` | Сначала `Base`, затем поля и тело `Derived` |
| Поля класса | Создаются в порядке объявления |
| IS-A / HAS-A | Наследование / содержание объекта |
| `delete` через `Base*` | Нужен виртуальный деструктор |
| `override` | Проверяет переопределение virtual-метода |
| `Base = Derived` по значению | Object slicing |
| `virtual f() = 0` | Чисто виртуальная функция, класс абстрактный |
| `unique_ptr<Shape>` | Владеет объектом и удаляет его автоматически |
| Вызов из `Base()` / `~Base()` | Вызывается реализация `Base` |
