# Практика 06 — Наследование, полиморфизм и виртуальные функции

[[Практики по C++|← К списку практик]]

Материал занятия по лекции 12.

## 1. `override`

Если метод базового класса объявлен как `virtual`, его можно переопределить в наследнике:

```cpp
class Button {
public:
    virtual void draw();
};

class ColoredButton : public Button {
public:
    void draw() override;
};
```

`override` просит компилятор проверить, что метод действительно переопределяет виртуальный метод базового класса. Поэтому опечатка или несовпадение параметров станет ошибкой компиляции.

```cpp
void drawButton() override; // ошибка: в Button нет такого virtual-метода
```

Если переопределяется виртуальный метод, следует писать `override`.

### `override` и перегрузка

`override` — переопределение метода базового класса в наследнике.

Перегрузка (*overload*) — несколько функций с одинаковым именем, но разными параметрами:

```cpp
void exec(int x);
void exec(float x);
```

## 2. Связные списки

### Односвязный список

Каждый узел односвязного списка хранит значение и указатель на следующий узел:

```cpp
int value;
List* next;
```

```text
[5 | next] -> [10 | next] -> [20 | nullptr]
```

В учебном примере `List` одновременно является и списком, и его узлом. У такого дизайна есть недостатки: список не может быть пустым, а многие операции требуют прохода по всем узлам.

### `push_back`

Чтобы добавить значение в конец, нужно дойти до последнего узла:

```cpp
List* current = this;

while (current->next != nullptr)
    current = current->next;

current->next = new List(value);
```

### Двусвязный список

В двусвязном списке у узла есть ещё и указатель на предыдущий элемент:

```cpp
DoubleList* prev;
```

```text
nullptr <- [5] <-> [10] <-> [20] -> nullptr
```

Конструктор может вызвать конструктор базового класса через список инициализации:

```cpp
DoubleList::DoubleList(int value)
    : List(value), prev(nullptr)
{}
```

При добавлении в конец надо связать оба узла:

1. Дойти до последнего узла.
2. Создать новый узел.
3. Записать `old.next = new`.
4. Записать `new.prev = old`.

### Важные ошибки в `DoubleList`

**Доступ к полям.** Если `List::next` объявлен как `private`, наследник не может обратиться к нему. Для учебного дизайна поле должно быть `protected`:

```cpp
protected:
    int value;
    List* next;
```

**Не виртуальный `push_back`.** Вызов через `List*` выберет реализацию `List`, если метод не виртуальный:

```cpp
class List {
public:
    virtual void push_back(int value);
};

class DoubleList : public List {
public:
    void push_back(int value) override;
};
```

**Преобразование указателей.** `next` имеет тип `List*`, поэтому присвоить его `DoubleList*` без явного преобразования нельзя.

```text
Derived* -> Base*    можно неявно
Base* -> Derived*    нельзя неявно
```

Любой `DoubleList` — это `List`, но не любой `List` — это `DoubleList`. Если реальный тип объекта точно известен, допустимо явное преобразование; в обычном коде безопаснее проверить его через `dynamic_cast`.

## 3. Полиморфизм

Функция может работать с общим интерфейсом базового класса:

```cpp
void fill(List* list, int value, size_t num) {
    for (size_t i = 0; i < num; ++i)
        list->push_back(value);
}
```

Если `push_back` виртуальный, при передаче `DoubleList` вызовется его реализация. Один код работает с базовым интерфейсом, а наследники задают своё поведение.

## 4. Пример: логирование

Базовый класс описывает общий интерфейс для разных приёмников логов:

```cpp
class Sink {
protected:
    Level level_;

public:
    Sink(Level level) : level_(level) {}
    virtual ~Sink() {}
    virtual void log(Level level, const char* message) {}
};
```

```text
Sink
├── StdoutSink
└── FileSink
```

Например, наследник может писать сообщения в стандартный вывод:

```cpp
class StdoutSink : public Sink {
public:
    void log(Level level, const char* message) override {
        if (level >= level_)
            printf("%s", message);
    }
};
```

У базового класса, предназначенного для работы через указатель на базовый тип, деструктор должен быть виртуальным. Тогда `delete Sink*` корректно уничтожит и часть объекта наследника.

## 5. Object slicing

Наследников нельзя хранить по значению как объекты базового класса:

```cpp
FileSink fileSink(...);
Sink sinkCopy = fileSink;
```

При таком копировании создаётся объект именно типа `Sink`; данные, принадлежащие только `FileSink`, теряются. Это называется **object slicing**.

Указатель не создаёт новый базовый объект, поэтому срезания нет:

```cpp
FileSink fileSink(...);
Sink* sink = &fileSink;
```

`sink` указывает на настоящий `FileSink`, и виртуальный вызов `log()` выберет `FileSink::log()`.

### Владение в `Logger`

```cpp
class Logger {
private:
    Sink* sinks_[100];
    size_t size_;

public:
    Logger() : size_(0) {}

    void addSink(Sink* sink) {
        sinks_[size_++] = sink;
    }

    ~Logger() {
        for (size_t i = 0; i < size_; ++i)
            delete sinks_[i];
    }
};
```

Здесь `Logger` становится владельцем переданных указателей. `delete` вызывает виртуальный деструктор реального объекта, затем деструктор базовой части и освобождает память. Повторное удаление одного и того же объекта приводит к `double free`.

В современном C++ такое владение лучше выразить через `std::unique_ptr<Sink>`.

## 6. Pure virtual и абстрактные классы

Обычный виртуальный метод можно не переопределять. Pure virtual метод требует реализации от конкретного наследника:

```cpp
class Sink {
public:
    virtual void log(Level level, const char* message) = 0;
};
```

Класс хотя бы с одним pure virtual методом — **абстрактный**. Его экземпляр создать нельзя:

```cpp
Sink sink; // ошибка
```

Наследник, который не реализовал все pure virtual методы, тоже остаётся абстрактным:

```cpp
class FileSink : public Sink {
public:
    void log(Level level, const char* message) override;
};
```

`override` и pure virtual решают разные задачи:

- `override` проверяет, что метод корректно переопределяет базовый;
- `= 0` требует, чтобы конкретный наследник реализовал метод.

## 7. Static и dynamic dispatch

Без `virtual` реализация выбирается по типу указателя — это **static dispatch**:

```cpp
class Button {
public:
    void draw();
};

Button* button = new ColoredButton();
button->draw(); // Button::draw()
```

С `virtual` выбор идёт по реальному типу объекта — это **dynamic dispatch**:

```cpp
class Button {
public:
    virtual void draw();
};

class ColoredButton : public Button {
public:
    void draw() override;
};

Button* button = new ColoredButton();
button->draw(); // ColoredButton::draw()
```

```text
не virtual -> выбор по типу указателя
virtual     -> выбор по реальному типу объекта
```

## 8. `vtable` и `vptr`

Для классов с виртуальными методами компилятор обычно создаёт таблицу указателей на виртуальные функции — **vtable**:

```text
vtable
├── &draw
├── &click
└── ...
```

В объекте обычно есть скрытый указатель `vptr`, который указывает на соответствующую таблицу:

```text
vptr -> vtable
```

Это распространённая реализация механизма виртуальных функций, но точное устройство не гарантируется стандартом C++.
