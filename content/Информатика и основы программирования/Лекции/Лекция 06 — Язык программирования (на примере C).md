## 1. По какому критерию выбирать язык программирования? (слайды 1–2)

**Абсолютно лучшего языка программирования нет:** выбор зависит от задачи и критерия оценки.

| Критерий | Что оценивается |
|---|---|
| Быстродействие | Производительность **готовой программы** |
| Надёжность | Насколько легко допустить случайную ошибку и насколько язык помогает её предотвратить |
| Библиотеки | Доступность готового кода для конкретных задач |
| Популярность | Распространённость, доступность специалистов, документации и инструментов |
| Экономическая эффективность | Стоимость разработки, поддержки и эксплуатации |

**TCO (Total Cost of Ownership — совокупная стоимость владения)** включает разработку, сопровождение, исправление ошибок, эксплуатацию и развитие ПО. Иногда важнее быстро выпустить продукт, иногда — снизить многолетние расходы и риски. Критерии «первый изученный» и «без фигурных скобок» показывают, что субъективный вкус сам по себе не делает язык объективно лучшим.

**Вывод:** выбирать язык нужно **под задачу** и обосновывать выбор, а не объявлять универсального победителя.

## 2. Ассемблер и языки высокого уровня (слайды 3–4)

**Язык ассемблера (assembly language)** — низкоуровневый язык, в котором инструкции процессора записаны **мнемониками** — короткими текстовыми именами команд. Ассемблер (программа-транслятор) преобразует эти записи в машинные инструкции целевой архитектуры.

- **Регистр** — небольшое высокоскоростное хранилище внутри процессора; команды ассемблера часто явно указывают регистры.
- Ассемблер — **семейство языков**, а не один универсальный язык: набор команд и регистров зависит от архитектуры (например, x86-64 или ARM).
- Иногда ассемблеры предоставляют дополнительные макросы и конструкции, похожие на высокоуровневые циклы и ветвления.

**Исходный пример из лекции:** [Compiler Explorer — пример ассемблера](https://godbolt.org/z/6cTbY7nr6).

**Почему возникла проблема переносимости.** Программа на ассемблере тесно связана с набором инструкций конкретного процессора. При переходе на другую архитектуру код приходится существенно перерабатывать. Когда в 1960–1970-е годы стало больше несовместимых машин, такое переписывание оказалось дорогостоящим.

**АЯВУ — алгоритмические языки высокого уровня (HLL, High-Level Languages)** позволяют описывать вычисления без прямого перечисления машинных команд. Компилятор переводит один исходный код в инструкции нужной архитектуры. Это основа **переносимости (portability)**, хотя платформенно-зависимый код и особенности библиотек могут потребовать доработок.

В маломощных микроконтроллерах аппаратных операций бывает меньше, чем у процессоров общего назначения. Например, если инструкции произвольного умножения нет, компилятор может реализовать его последовательностью команд; умножение беззнакового значения на $2^n$ часто сводится к сдвигу влево на $n$ бит (при соблюдении условий применимости).

## 3. Происхождение C, Unix и разработчики (слайды 5–7)

Язык **C** появился при развитии операционной системы **Unix**. Раннюю Unix писали на ассемблере для **PDP-7** (PDP — *Programmed Data Processor*, семейство компьютеров DEC). При переносе на PDP-11 понадобился более переносимый инструмент.

Историческая линия:

| Год | Событие |
|---|---|
| **1967** | Мартин Ричардс создал **BCPL (Basic Combined Programming Language)** — упрощение CPL (Combined Programming Language). |
| **Около 1969** | Кен Томпсон разработал **B** на основе BCPL; в его развитии участвовал Деннис Ритчи. B не имел привычной системы типов. |
| **1972** | Деннис Ритчи разработал C как развитие B с типами данных; язык использовали при работе над Unix. |
| **1973** | Появилось `struct`, позволившее объединять данные в структуры. |
| **1978** | Брайан Керниган и Деннис Ритчи опубликовали *The C Programming Language* (**K&R**); это описание C уже близко к привычному языку. |

**Исторический пример со слайда:** ранний синтаксис вычитания с присваиванием использовал `i =- 5`, что визуально смешивалось с присваиванием отрицательного числа. Современная запись устраняет неоднозначность:

```c
// Дополнение: современная иллюстрация неоднозначности
// i =- 5;  // старая запись операции вычитания с присваиванием
i -= 5;     // вычесть 5 из i
i = -5;     // присвоить i значение -5
```

**Предшественники Unix:** среди ранних систем с использованием языков высокого уровня в лекции названы ОС для **Burroughs B5000** (Algol, 1961) и **Multics** (PL/I, середина 1960-х). Unix не была первой подобной системой, но стала чрезвычайно влиятельной.

**Персоналии:**

- **Кен Томпсон (Ken Thompson)** — Unix, B, `grep` и работа с регулярными выражениями; участвовал в разработке **UTF-8 (Unicode Transformation Format, 8-bit)** и Go.
- **Деннис Ритчи (Dennis Ritchie)** — главный создатель C, один из создателей Unix; позднее работал над **Plan 9** и **Inferno**.
- **Брайан Керниган (Brian Kernighan)** — соавтор книги K&R, участвовал в создании AWK; сам подчёркивал, что язык C — прежде всего работа Ритчи.
- Томпсон и Ритчи получили **премию Тьюринга в 1983 году** за вклад в теорию и реализацию операционных систем, прежде всего Unix.

На слайдах также различаются **hacker** — исторически технический энтузиаст и исследователь — и **cracker** — человек, взламывающий защиту. В современном употреблении терминология бывает менее строгой.

## 4. Стандарты C и флаг `-std=` (слайд 8)

**Стандарт C** задаёт правила языка и требования к стандартной библиотеке, чтобы независимые реализации были совместимы. **ANSI (American National Standards Institute)** — американский институт стандартизации; **ISO (International Organization for Standardization)** — международная организация по стандартизации.

| Стандарт | Существенные изменения |
|---|---|
| **C89 / C90** | Первый стандарт ANSI (1989), затем ISO (1990); база современного C. |
| **C99** | Однострочные комментарии `//`, `long long`, `_Complex`, `inline`, `restrict`, уточнения арифметики с плавающей точкой. |
| **C11** | Средства атомарных операций и многопоточности. |
| **C18** | Преимущественно исправления и уточнения C11. |
| **C23** | `bool`, `true`, `false` стали ключевыми словами; также добавлены, в частности, `nullptr`, `typeof`, `constexpr` для объектов, `#embed`, новые возможности `auto`; убраны старые K&R-определения функций. Стандарт опубликован как ISO/IEC 9899:2024. |

**Примеры указания стандарта (суть рекомендации преподавателя):**

```bash
gcc -std=c99 prog.c -o prog
gcc -std=c11 prog.c -o prog
```

Без `-std=` режим по умолчанию зависит от компилятора и его версии. По материалам лекции **C99/C11** остаются важны для совместимости со старыми реализациями и проектами; пример — **tcc (Tiny C Compiler)** и проект **GNU Mes**, связанный с построением проверяемой цепочки начальной сборки (*bootstrap*).

**Почему в C99 появился `_Bool`, а не `bool`?** Имя `bool` могло уже использоваться в старом коде как обычный идентификатор. Имена с подчёркиванием и заглавной буквой заранее резервировались для реализации, поэтому добавление `_Bool` реже ломало существующие программы. В C99–C18 удобное имя `bool` предоставлял заголовок `<stdbool.h>`; в C23 `bool` стало ключевым словом, а `_Bool` сохранился.

> **Уточнение:** `auto` в C99/C11 — спецификатор автоматического времени хранения; в C23 у него появилась также возможность вывода типа по инициализатору. Различать версии стандарта обязательно.

## 5. Оригинальные примеры BCPL и B (слайды 9–10)

### 5.1. BCPL: `VALOF` и `RESULTIS`

**Пример слайда 9 (сохранён полностью):**

```text
GET "LIBHDR"

LET START() = VALOF $(
    FOR I = 1 TO 5 DO
        WRITEF("%N! = %I4*N", I, FACT(I))
    RESULTIS 0
$)

AND FACT(N) = N = 0 -> 1, N * FACT(N - 1)
```

Программа печатает факториалы чисел **1–5**:

- `GET "LIBHDR"` — подключение библиотечного заголовка.
- `FOR I = 1 TO 5 DO` — цикл по `I`.
- `WRITEF(...)` — форматированный вывод числа и `FACT(I)`.
- `FACT(N)` — рекурсивный факториал: при `N = 0` возвращается `1`, иначе `N * FACT(N - 1)`.
- Конструкция `N = 0 -> 1, N * FACT(N - 1)` — условное выражение (по идее соответствует `N == 0 ? 1 : N * FACT(N - 1)` в C).
- `VALOF $( ... $)` — **блок операторов, имеющий значение как выражение**; `RESULTIS 0` завершает его вычисление и задаёт значение `0`.

**Суть `RESULTIS`:** это **не печать**. После выполнения цикла всё выражение `VALOF ...` получает значение `0`; функция `START()` возвращает именно его. Особенность BCPL — объединение последовательности действий и возвращаемого значения в одной конструкции.

### 5.2. B: машинное слово без объявленного типа

**Пример слайда 10 (сохранён полностью):**

```c
printn(n, b) {
        extrn putchar;
        auto a;

        if (a = n / b)   /* assignment, not test for equality*/
                printn(a, b); /* recursive */
        putchar(n % b + '0');
}
```

Это рекурсивная печать неотрицательного целого `n` в системе счисления с основанием `b` (в данном варианте — для цифр `0`–`9`):

1. `a = n / b` получает целую часть от деления на основание.
2. Если `a != 0`, вызывается `printn(a, b)` — сначала печатаются старшие цифры.
3. `n % b + '0'` получает символьный код последней цифры, `putchar` печатает её.

`extrn putchar` — обращение к внешней функции; `auto a` — локальная переменная с автоматическим временем хранения; `if (a = n / b)` **присваивает** значение `a`, затем проверяет результат присваивания на ненулевость. Это не сравнение `==`.

**Как здесь представлены данные?** В B нет объявлений `int`, `float` и подобных типов: переменные вроде `a` и параметров `n`, `b` в базовой модели содержат **машинные слова** — группы битов характерной для машины длины. В коде не требуется писать `word`: это способ представления значений по умолчанию. Число и адрес различаются тем, как программа использует биты, а не системой типов, привычной по C.

## 6. Почему C сохранил популярность (слайды 11–12)

В лекции подчёркивается длительное применение C в системном программировании: ядрах ОС, низкоуровневых библиотеках, прошивках, реализациях языков. Например, **CPython** — основная реализация Python — преимущественно написана на C. **TIOBE** на слайде использован как пример рейтинга популярности; рейтинг измеряет косвенные показатели публичной распространённости, **а не долю реального исходного кода**.

Сочетание свойств C:

- **Близость к аппаратуре:** указатели, управление размещением и представлением данных.
- **Переносимость исходного кода:** компиляция под разные целевые архитектуры.
- **Относительно небольшая языковая среда выполнения:** нет обязательного сборщика мусора и управляемого рантайма.
- **Цена контроля:** высокий риск ошибок памяти, неопределённого поведения и сложность обеспечения безопасности.

Утверждения «Rust / Go / Java лучше C» имеют смысл **только с указанными задачей и критерием**: например, безопасность памяти или скорость разработки могут оказаться важнее прямого низкоуровневого контроля.

## 7. Парадигмы и технологические характеристики C (слайд 13)

**Парадигма программирования** — подход к организации вычислений и кода. Три подхода, выделенные преподавателем, **не взаимоисключают друг друга**:

| Подход | Главная идея | Признак в C |
|---|---|---|
| **Императивное** | Программа задаёт **команды, изменяющие состояние**. | Присваивания, изменение переменных. |
| **Структурное** | Поток выполнения организован **последовательностью, ветвлениями и циклами**, без необходимости хаотичных переходов. | `if`, `while`, `for`, `do ... while`. |
| **Процедурное** | Код организован в **процедуры/функции с параметрами и локальными переменными**. | Определение и вызов функций. |

В классификации лекции это развитие **императивный → структурный → процедурный подход**; речь не о выборе одного из трёх режимов. Обычная функция C с переменными, циклами и ветвлениями использует все три подхода. **Структурное программирование допускает функции**; процедурное дополнительно подчёркивает организацию кода на уровне функций.

Технические особенности C:

- **Раздельная трансляция (separate compilation):** единицы трансляции компилируются отдельно, объектные файлы соединяются редактором связей.
- **Препроцессор (preprocessor):** директивы `#include`, `#define` и др. обрабатываются до собственно компиляции.
- **Нет встроенных пространств имён и системы модулей как в C++:** конфликты имён предотвращаются соглашениями (`library_print`), а внутреннее связывание (`static`) помогает скрывать вспомогательные имена.

**Namespace (пространство имён)** — механизм логической группировки имён, позволяющий иметь одинаковые короткие имена в разных группах. В C++ возможно `First::print()` и `Second::print()`; в C обычно используют префиксы (`first_print`, `second_print`). *Это дополнительная иллюстрация, не код со слайда.*

## 9. Лексика C: токены и ключевые слова (слайды 15–16)

**Токен** — элементарная значимая единица текста программы. На слайде перечислены следующие категории:

| Категория | **Оригинальные примеры лекции** | Значение |
|---|---|---|
| Пробельные символы (*whitespace*) | Пробел, табуляция, новая строка | Разделяют токены. |
| Комментарии | `/* ... */`, `// ...` | Не участвуют в выполнении программы. |
| Десятичные целые литералы | `100500L` | `L` указывает целочисленный тип семейства `long`. |
| Шестнадцатеричные литералы | `0xBADF00D` | `0x` обозначает основание 16. |
| Литералы с плавающей точкой | `1.5`, `.4`, `1.7e+2`, `.3f` | `1.7e+2 = 170`; `f` задаёт `float`. |
| Символьный/строковый литерал | `'A'`, `"literal string"` | Значение символа / строковый литерал. |
| Операции и разделители | `=`, `/=`, `{`, `}` | Действия и синтаксические знаки. |
| Ключевые слова | `if`, `int`, `return` | Зарезервированные слова языка. |
| Идентификаторы | `abc`, `main`, `printf` | Имена сущностей. |

**Идентификатор** — имя переменной, функции или другой именованной сущности. **Ключевое слово** — слово, закреплённое за синтаксисом языка; использовать его как имя переменной или функции нельзя. Например, `printf` — идентификатор библиотечной функции, **не** ключевое слово.

**Комментарии C не вложены:**

```c
/* первый /* второй */
```

Первый `/*` открывает комментарий, второй находится **внутри** комментария как текст, первый `*/` закрывает его. Второго независимого уровня вложенности нет.

**Суффиксы целочисленных литералов**, перечисленные преподавателем: `U` (*unsigned*), `L` (*long*), `UL`, `LL` (*long long*), `ULL`; регистр суффиксов может варьироваться. Они задают категорию целочисленного типа (например, `100ULL` — `unsigned long long`). Для вещественных литералов есть другие суффиксы: `.3f` — `float`, `1.5L` — `long double`.

**Группы ключевых слов C89 (исходный список):**

- **Управление:** `break`, `case`, `continue`, `default`, `do`, `else`, `for`, `goto`, `if`, `return`, `switch`, `while`.
- **Типы и конструкторы типов:** `char`, `double`, `enum`, `float`, `int`, `long`, `short`, `signed`, `struct`, `typedef`, `union`, `unsigned`, `void`.
- **Спецификаторы/квалификаторы:** `auto`, `const`, `extern`, `register`, `static`, `volatile`.
- **Оператор:** `sizeof` — размер типа или выражения в байтах C.

**В C99** добавлены, в частности, `_Bool`, `_Complex`, `_Imaginary`, `inline`, `restrict`.

**Имена с `_`.** Стандарт резервирует ряд идентификаторов для реализации языка (например, начинающихся с `_` и заглавной буквы, либо с `__`). Это позволяет расширять язык, не занимая распространённые пользовательские имена. В собственном коде следует избегать зарезервированных имён.

## 10. Синтаксис. Объявление и определение (слайд 17)

**Синтаксис** устанавливает допустимый порядок токенов. Блоки могут обозначаться `{}` (C, Java, Rust), `begin/end` (Algol, Pascal и др.), отступами (Python, Haskell). В C `;` — **терминатор оператора/объявления**, а не просто разделитель. Одиночный `;` — допустимый **пустой оператор**.

**Программа на C** состоит из объявлений (*declarations*) и определений (*definitions*) объектов, функций и типов.

- **Объявление (declaration)** сообщает компилятору имя и правила его использования (например, тип и параметры функции).
- **Определение (definition)** создаёт сам объект или задаёт реализацию функции. Оно также служит объявлением, но обратное неверно.

**Дополнительная иллюстрация:**

```c
int sum(int a, int b);          // Объявление функции: тела нет
int sum(int a, int b) {         // Определение функции: реализация есть
    return a + b;
}

extern int count;               // Объявление внешней переменной
int count = 5;                  // Определение переменной
```

Объявление функции позволяет проверить вызов **до обнаружения реализации**. Но если при сборке определение нигде не найдено, линкер выдаёт ошибку вроде `undefined reference to 'sum'`.

**Раздельная трансляция и единица трансляции:** препроцессор формирует из одного исходного `.c` с включёнными заголовками единицу трансляции (*translation unit*). Компилятор обрабатывает её отдельно. **Linkage (связывание имени)** — правило языка, определяющее, обозначает ли одно имя одну сущность в разных местах программы; **linker (редактор связей)** — инструмент, который объединяет объектные файлы и разрешает внешние ссылки. Термины связаны, но не тождественны.

## 11. Семантика C и порядок вычислений (слайд 18)

**Семантика** — смысл конструкций языка. Для обычной программы C основная точка входа — `main()`; до неё происходит необходимая инициализация, в том числе статических данных, а при нормальном завершении могут выполняться зарегистрированные через `atexit()` функции. Функция с возвращаемым типом `void` не возвращает значения.

**Важнейший пример слайда:**

```c
func3(func1(), func2());
```

**Оба** вызова `func1()` и `func2()` выполняются до фактического вызова `func3()`, но **порядок двух внутренних вызовов не определён стандартом**: допустим и `func1 → func2`, и `func2 → func1`. Аналогично не стоит полагаться на порядок вычисления операндов в большинстве арифметических выражений.

Это сделано в том числе ради свободы оптимизации. **Отсутствие гарантированного порядка само по себе не означает неопределённое поведение.**

**UB (Undefined Behavior — неопределённое поведение)** — ситуация, для которой стандарт языка не предъявляет требований к результату выполнения. Например, при 32-битном `int` переполнение `2147483647 + 1` для знакового целого — UB. Оно отличается от *неуточнённого порядка вычисления*, когда стандарт допускает несколько конкретных вариантов.

## 12. Типы, представление данных и строки (слайд 19)

**Тип данных** задаёт: **(1) представление/размещение значений в памяти** и **(2) семантику операций над ними**. У встроенных типов C набор относительно невелик:

- Целочисленные: `char`, `short`, `int`, `long`, `long long`; для подходящих типов — варианты `signed`/`unsigned`.
- Вещественные: `float`, `double`, `long double`.
- Логический: `_Bool` (начиная с C99), в C23 ключевое слово `bool`.
- Комплексные: `_Complex` (C99).
- Указатели и составные типы: `struct`, `union`, массивы `[]`.

**Почему `char` — целочисленный тип?** Символ хранится как числовой код. В ASCII-совместимом наборе `'A'` соответствует коду `65`, и операции с `char` используют целочисленную арифметику. **Байт C** — единица размера `sizeof(char) == 1`; типичны 8-битные байты, но стандарт не гарантирует ровно 8 бит на всех архитектурах.

**Составные типы:**

| Тип | Размещение |
|---|---|
| `struct` | Поля имеют отдельные области памяти (возможны промежутки для выравнивания). |
| `union` | Поля разделяют одну область памяти; интерпретация тех же байтов зависит от выбранного поля и правил языка. |
| Массив `[]` | Элементы одного типа расположены последовательно. |

В C нельзя произвольно **перегружать операторы** для собственных структур, как в C++; при этом допустимы предусмотренные языком операции, например присваивание структур одинакового типа.

**Встроенного самостоятельного строкового типа в C нет.** Строка в обычной модели C — последовательность `char`, завершающаяся нулевым символом `\0`. Например, литерал `"Cat"` при хранении как массив `char` занимает четыре элемента: `'C'`, `'a'`, `'t'`, `'\0'`.

## 13. Выражения, присваивание и гарантированный порядок (слайд 20)

**Выражение (expression)** — синтаксическая конструкция, при вычислении которой получается значение (или, для `void`-выражения, вычисление без значения). **Value** — результат вычисления.

В C **присваивание — тоже выражение**: результат `b = 5` имеет значение `5`, поэтому корректно:

```c
// Дополнительная иллюстрация
int a, b;
a = b = 5;   // Сначала b получает 5, затем a получает 5
```

**Важные исключения, где порядок вычисления специально определён:**

| Оператор | Поведение |
|---|---|
| `,` (оператор запятая) | Сначала левое выражение, потом правое; значение — у правого. |
| `a ? b : c` | Сначала `a`; вычисляется **только** `b` при истинном `a` или `c` при ложном. |
| `&&` — логическое И | Если слева ложь, справа **не вычисляется**. |
| `||` — логическое ИЛИ | Если слева истина, справа **не вычисляется**. |

**Оригинальный пример из комментариев:** `a = (x, y)` — вычисляется `x`, затем `y`, и в `a` присваивается значение `y`.

Не путать **оператор запятая** с запятой, разделяющей аргументы: `func(x, y)` **не** задаёт порядок вычисления `x` и `y`. В `f() + g()` порядок вызовов также не гарантируется. Выражение `2 + 3;` допустимо: результат просто не используется.

## 14. L-value и R-value (слайд 21)

Названия исторически происходят от *left/right value*, но **категория выражения не определяется его буквальным положением слева или справа от `=`**.

- **L-value** — выражение, **обозначающее объект**; например, имя переменной `x`. В C существует также понятие *modifiable lvalue* — l-value, в который разрешено записывать.
- **R-value** — удобное учебное обозначение вычисленного значения, не обозначающего самостоятельный объект (например, числовой литерал `5` или результат `x + 3`). Терминология стандарта C отличается от классификации выражений C++.

**Дополнительная иллюстрация:**

```c
int x = 5;
int y = x + 3;
// x и y обозначают объекты: l-value
// 5 и (x + 3) — вычисленные значения
// &x — допустимо; &(x + 3) и &5 — недопустимы
```

Важно: `x` остаётся **l-value даже справа** в `y = x;`. `const int x = 5;` также даёт l-value, но оно не модифицируемо. **Не у всех l-value можно брать адрес**: исключения — например, битовое поле структуры или переменная со спецификатором `register`. Тип `void` не имеет обычных значений.

## 15. Область видимости, время хранения, связывание. Модификаторы (слайд 22)

Для экзамена важно разделять **три разных свойства**:

1. **Область видимости (scope)** — в какой части исходного текста доступно **имя**.
2. **Время хранения (storage duration)** — как долго существует **сам объект**.
3. **Связывание (linkage)** — могут ли объявления одного имени в разных местах означать **одну сущность**.

| Спецификатор | Основная идея |
|---|---|
| `auto` | Для локального объекта: автоматическое время хранения; в C99/C11 обычно не пишется явно. |
| `static` | Локально: объект сохраняется между вызовами; на уровне файла: внутреннее связывание имени. |
| `extern` | Используется для обращения к объявлению с внешним связыванием, определение может быть в другом модуле. |
| `register` | Историческая просьба хранить значение в регистре; в C запрещает брать `&` от такой переменной. |
| `const` | Не позволяет модифицировать объект через данное квалифицированное l-value. |
| `volatile` | Существенные чтения/записи нельзя произвольно устранять: значение может изменяться вне обычной логики программы. |
| `inline` | Связано с возможностью встраивания тела функции; **не гарантирует** фактического встраивания. |
| `restrict` | Обещание программиста об особенностях доступа к памяти через указатель, позволяющее оптимизации. |

### `auto` и локальный `static`

**Дополнительный пример:**

```c
void f(void) {
    int a = 0;          // как auto int a = 0; (C11)
    static int b = 0;
    ++a;
    ++b;
    printf("%d %d\n", a, b);
}
```

При последовательных вызовах `f()` результаты будут `1 1`, затем `1 2`, затем `1 3`: `a` создаётся заново при каждом входе, а `b` существует всё время выполнения программы. Автоматическое время хранения **не гарантирует физического размещения строго на стеке**: возможны регистры и оптимизации.

### `static` на уровне файла, `extern` и единицы трансляции

```c
// Дополнительная иллюстрация: data.c
int counter = 5;             // Определение, внешнее связывание
static int hidden = 7;       // Имя имеет внутреннее связывание

// Дополнительная иллюстрация: main.c
extern int counter;          // Ссылаемся на определение из data.c
```

`counter` доступен другим единицам трансляции через корректное внешнее объявление; `hidden` нельзя найти из другого `.c` по этому имени. Для **локальной переменной** `static` означает **время хранения**, а для **имени на уровне файла** — **внутреннее связывание**. Сочетать эти два смысла нельзя автоматически.

### `const`, `volatile`, `inline`, `restrict`

- `const int x = 5;` — присваивание `x = 6;` запрещено. При этом `const` **не равен** «значение обязательно вычислено компилятором заранее».
- `volatile` нужен, например, при чтении отображённого в память регистра устройства: компилятор не должен устранять значимые повторные обращения. **`volatile` не даёт атомарности и сам по себе не делает обмен между потоками безопасным.**
- `inline` не гарантирует замену вызова на тело: компилятор решает, выгодно ли это; правила `inline` касаются и связывания определений.
- `restrict` — для оптимизации кода с указателями: программист обещает, что определённые обращения к изменяемому объекту в данном контексте не будут конфликтовать через посторонние указатели.

**Дополнительная иллюстрация для `restrict`:**

```c
void add(int *restrict a, int *restrict b) {
    *a += *b;
}

int x = 10, y = 5;
add(&x, &y);  // корректно: x станет 15
add(&x, &x);  // нарушает restrict-контракт; UB
```

Без соответствующей гарантии компилятор вынужден учитывать **aliasing (алиасинг)** — ситуацию, когда несколько указателей обращаются к одному объекту. `restrict` не делает проверку во время исполнения, а возлагает соблюдение контракта на программиста. Формальные правила несколько точнее, чем простое «все адреса различны».

## 16. Управляющие конструкции C (слайды 23–24)

**Управляющие конструкции** определяют порядок выполнения операторов:

| Конструкция | Семантика |
|---|---|
| Последовательность | Выполнить первый оператор, затем следующий. |
| `if / else` | Выбрать ветвь по условию. |
| `while` | **Предусловие:** проверить условие до тела; возможно ноль итераций. |
| `for` | В C — цикл с предусловием, дополненный выражениями инициализации и шага. |
| `do ... while` | **Постусловие:** выполнить тело, затем проверить условие; минимум одна итерация. |
| `switch` / `case` | Вычислить целочисленное управляющее выражение и перейти к подходящей метке. |
| `goto` | Безусловно перейти к метке **в пределах функции**. |

**Оригинальные конструкции со слайда:**

```c
// Иллюстративная запись синтаксиса из презентации
goto SomeLabel;
for (;;) { }
do { } while (condition);
switch (x) { case 1: /* ... */ break; default: /* ... */ }
```

В **C нет отдельного строгого «цикла со счётчиком»**: `for` может не иметь счётчика (`for (;;)`), его переменные можно менять в теле, три части заголовка могут быть произвольными допустимыми выражениями. В отличие от более строгих конструкций некоторых других языков, `for` C не обещает выполнение ровно заданного числа итераций.

**`switch` — это не автоматически независимые ветви.** Он передаёт управление на метку внутри блока; при отсутствии `break` выполнение **проваливается (fall-through)** к следующим операторам и меткам.

```c
// Дополнительная иллюстрация
int x = 1;
switch (x) {
    case 1: printf("A");
    case 2: printf("B"); break;
    default: printf("C");
}
// Вывод: AB
```

**`goto` не запрещён языком.** Практический пример — единая метка `cleanup` для освобождения нескольких ресурсов при ошибке. Опасность заключается в запутанном и неконтролируемом потоке управления, а не в существовании самой инструкции.

**Duff's device (устройство Даффа)** — нестандартный на вид, но исторически известный приём, совмещающий `switch` и `do ... while` ради **развёртки цикла (loop unrolling)** без отдельной обработки оставшихся итераций. Возможен благодаря механизму перехода к метке внутри блока `switch`. Его важно **узнавать и уметь объяснить**, а не считать обычным стилем написания циклов.

## 17. Подпрограммы, процедуры, рекурсия (слайды 25–26)

**Подпрограмма (subroutine)** в историческом смысле — именованный участок кода, который можно выполнить и затем вернуться к вызвавшему месту. Примеры старых механизмов: `GOSUB` в BASIC (*Beginner's All-purpose Symbolic Instruction Code*), `PERFORM` в COBOL (*Common Business-Oriented Language*).

**Процедура (procedure)** — подпрограмма с **параметрами и собственными локальными переменными** каждого вызова. Именно независимость вызовов делает удобными повторное использование кода и рекурсию. В C процедуры реализуются функциями; функции могут возвращать значение или быть типа `void`.

**Рекурсия** — прямой или косвенный вызов функции самой себя:

- Прямая: `A() → A()`.
- Косвенная: `A() → B() → A()`.
- Просто `A() → B()` **не является** рекурсией.

При рекурсивных вызовах каждому вызову требуется отдельное состояние параметров и автоматических локальных переменных. Для этого обычные реализации используют **стек вызовов (call stack)**, состоящий из **кадров (stack frames)**. Возвращаясь из вложенного вызова, программа восстанавливает данные предыдущего.

## 18. История структурного программирования и теорема Бёма — Якопини (слайд 27)

| Год | Вклад | Суть |
|---|---|---|
| **1958** | **Fortran II**, Джон Бэкус (IBM) | Подпрограммы с параметрами; статическая организация данных в тогдашней модели препятствовала обычной рекурсии. |
| **1960** | **Algol 60** | Собственные локальные переменные каждого вызова, стековая модель и рекурсия; синтаксис описывался формальной грамматикой. |
| **1966** | **Коррадо Бём и Джузеппе Якопини** | Теорема о достаточности структурных управляющих конструкций. |
| **1968** | **Эдсгер Дейкстра** | Письмо *Go To Statement Considered Harmful* о вреде недисциплинированных переходов. |
| **1972** | **C** | Использует структурные конструкции и процедуры, но сохраняет `goto`. |

**БНФ (Backus–Naur Form — форма Бэкуса — Наура)** — способ формально описывать синтаксис языка через правила грамматики; вклад Algol 60 существенно повлиял на теорию компиляторов.

**Структурное программирование** — подход к организации **потока управления** через **последовательность, ветвление и цикл**. Оно **не запрещает функции**, а процедурное программирование дополняет структурный стиль организацией кода в процедуры.

**Теорема Бёма — Якопини (1966):** любой вычислимый алгоритм можно выразить с помощью **последовательного выполнения, ветвления и повторения**, без необходимости использовать произвольный `goto` (при подходящей организации данных и управления).

**Что теорема НЕ говорит:** она не запрещает оператор `goto` в языке. Дейкстра выступал против **необозримого, недисциплинированного** управления потоком. C сохраняет `goto` для практических случаев, например выхода из сложной обработки ошибок к единой точке очистки ресурсов.

## 19. Стандартная библиотека C, `libc` и `libm` (слайд 28)

Стандарт **ISO/IEC 9899** регулирует **язык и стандартную библиотеку**. Функции `printf`, `malloc`, `strlen` — **библиотечные функции, а не ключевые слова**. В обычной среде стандарт описывает ожидаемое поведение этих функций.

**Заголовок vs библиотека:**

- `#include <stdio.h>` предоставляет **объявления**, по которым компилятор проверяет вызов `printf`.
- Реализация `printf` обычно находится в **`libc`** — библиотеке C; редактор связей сопоставляет внешний вызов с реализацией.
- **`libc` обычно подключается драйвером компилятора автоматически**, поэтому отдельный флаг `-lc` в типичной команде не нужен.

**Реализации `libc` со слайда:**

| Реализация | Типичная среда |
|---|---|
| **glibc (GNU C Library)** | Большинство дистрибутивов GNU/Linux. |
| **musl** | Например, Alpine Linux. |
| **newlib** | Встраиваемые системы и кросс-инструменты. |

**Hosted environment** — среда с полноценной стандартной библиотекой (например, обычная ОС). **Freestanding environment** — более ограниченная среда: полноценная библиотека C не обязательна; на «голом» микроконтроллере `printf` может вообще отсутствовать, пока кто-то не реализует вывод.

**Оригинальная команда со слайда:**

```bash
gcc prog.c -lm
```

Здесь `-l` означает поиск библиотеки при связывании, а `m` — математическую библиотеку **`libm`** (от *math*). В системах вроде GNU/Linux математические функции исторически находятся в отдельной `libm`, поэтому при использовании, например, `sqrt` часто нужен `-lm`. **`#include <math.h>` сам по себе не добавляет реализацию из `libm`**: он даёт объявления. На некоторых платформах (например, macOS) отдельный `-lm` обычно не нужен. *Уточнение: встраивание встроенных математических функций компилятором может влиять на необходимость связывания в конкретном примере; правило о различии заголовка и библиотеки остаётся неизменным.*

## 20. Встраиваемые системы и MISRA C (слайд 29)

**Embedded systems (встраиваемые системы)** — вычислительные устройства внутри приборов, датчиков и контроллеров. Они могут иметь очень мало оперативной и программной памяти и жёсткие ограничения энергопотребления.

**Оригинальный пример преподавателя:** у классического **ATtiny13** — **1024 байта флеш-памяти** под программу, **64 байта оперативной памяти (SRAM)**; в ядре нет аппаратной инструкции `MUL`. Поэтому стоимость даже отдельных машинных команд может быть важна.

В таких условиях сохраняют практический смысл:

- `goto` для одной точки освобождения ресурсов при ошибке;
- `do ... while` для опроса датчика с гарантированным хотя бы одним действием;
- `static` для хранения состояния вне автоматических локальных объектов;
- `switch`, в том числе редкие приёмы вроде Duff's device;
- замена некоторых умножений на степени двойки битовыми сдвигами, где это корректно.

**MISRA C** — набор рекомендаций/правил безопасного использования языка C, возникший в автомобильной отрасли. **MISRA** — *Motor Industry Software Reliability Association*. Его используют в критически важных встраиваемых системах для повышения проверяемости и надёжности программ.

**Принципиальная разница:**

- **Стандарт C** задаёт, какие конструкции допустимы и что они означают.
- **MISRA C** ограничивает способы написания кода ради предсказуемости, тестирования и проверки. Поэтому конструкция может быть **законной по C**, но **нежелательной или запрещённой конкретным правилом MISRA C** (например, некоторые формы `goto` и проваливания в `switch`).

## 21. Поиск ошибок: статический и динамический анализ (слайд 30)

**Статический анализ** исследует программу **без её запуска**; **динамический анализ** проверяет **выполняемый код**. Оба подхода полезны и дополняют друг друга.

| Средство | Назначение |
|---|---|
| **UBSan (UndefinedBehaviorSanitizer)** | При выполнении обнаруживает некоторые виды UB: знаковое переполнение, недопустимые сдвиги, часть ошибок обращения к объектам и др. |
| **ASan (AddressSanitizer)** | Ищет ошибки памяти: выход за границы, *use-after-free* (использование после освобождения) и др. |
| **Valgrind** | Инструментирует уже собранную программу, часто без перекомпиляции; за это приходится платить заметным замедлением. |

**Оригинальный пример со слайда:**

```c
int k = 2147483647;
k += 1;
```

Если `int` имеет максимум `2147483647`, операция вызывает **знаковое переполнение**, которое в C относится к UB.

**Оригинальная команда:**

```bash
gcc -fsanitize=undefined,address -g prog.c && ./a.out
```

- `-fsanitize=undefined,address` — включить проверки UBSan и ASan;
- `-g` — добавить отладочную информацию для сообщений об ошибках;
- `&& ./a.out` — выполнить программу после успешной сборки.

**Фрагмент оригинальной диагностики:**

```text
prog.c:3:5: runtime error: signed integer overflow:
2147483647 + 1 cannot be represented in type 'int'
```

**Ограничение:** динамические инструменты анализируют только **реально пройденные пути выполнения**. Если тесты не зашли в некоторую ветку `if`, скрытая в ней ошибка может остаться незамеченной. Поэтому их применяют вместе с хорошим тестовым покрытием и статическим анализом.

## 22. Материалы для самостоятельной проверки (слайд 31)

- **[Compiler Explorer](https://godbolt.org)** — сопоставление кода C и ассемблера, проверка влияния флагов и целевой архитектуры.
- Рекомендуемые преподавателем флаги: `-O2` (оптимизации), `-Wall`, `-Wextra` (предупреждения), `-pedantic` (дополнительные диагностики соответствия стандарту).
- **Duff's device** — ознакомиться с принципом развёртывания цикла через `switch` и `do ... while`.
- **Практические случаи `goto`** — обработка ошибок с одной точкой освобождения ресурсов, а не произвольные переходы ради усложнения кода.
