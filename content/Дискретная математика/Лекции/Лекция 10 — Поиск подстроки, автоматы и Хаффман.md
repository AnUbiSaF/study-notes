## 1. Наибольшая общая подпоследовательность (LCS)

**Задача.** Даны две строки. Требуется найти их общую *подпоследовательность* максимальной длины. Символы можно пропускать, **порядок менять нельзя**. В отличие от подстроки, символы подпоследовательности **не обязаны стоять подряд**.

### 1.1. Динамическое программирование

Пусть строки имеют длины `n` и `m`. В лекции используется таблица `V(i,j)`:

- `i` — число взятых символов первой строки;
- `j` — число взятых символов второй строки;
- `V(i,j)` — длина LCS этих двух префиксов (начальных частей строк).

**Зачем таблица:** маленькие задачи о префиксах решаются один раз, их результаты используются в следующих клетках. В правом нижнем углу, `V(n,m)`, находится **длина** искомой подпоследовательности.

> [!example] Дополнение — точная рекуррентная запись
> Обозначим `A[i]`, `B[j]` символы строк с **математической индексацией от 1**. Тогда
> 
> $$
> V(i,j)=\begin{cases}
> 0,&i=0\lor j=0,\\
> V(i-1,j-1)+1,&A[i]=B[j],\\
> \max\{V(i-1,j),V(i,j-1)\},&A[i]\ne B[j].
> \end{cases}
> $$
> 
> **Почему диагональ `−1,−1`:** совпавший последний символ берётся из **обеих** строк, значит, каждый из двух префиксов сокращается на один символ. Иначе можно посчитать один символ повторно.
> 
> **Почему максимум:** если последние символы разные, они не могут оба быть последним символом одной общей подпоследовательности. Следовательно, хотя бы один придётся исключить; выбирается лучший из двух вариантов.

### 1.2. Значение ответа и само решение — не одно и то же

В лекции отдельно подчёркивается: для экстремальной задачи обычно нужны **два результата**:

1. **Значение целевой функции** — здесь максимальная длина `V(n,m)`.
2. **Объект, на котором достигается максимум** — конкретная последовательность букв.

Число `5` не говорит, какие именно буквы образуют общую подпоследовательность, так же как длина кратчайшего маршрута не задаёт сам маршрут.

### 1.3. Восстановление через «скачки»

По формулировке лекции ищутся **скачки** — клетки, в которых значение увеличилось благодаря совпавшему символу. Символы из выбранных скачков образуют ответ. При движении назад по выбранным скачкам необходимо двигаться **и вверх, и влево**, иначе порядок символов нарушится.

**Дополнение — практический способ восстановить одну LCS из готовой таблицы:**

1. Начать в клетке `V(n,m)` — в правом нижнем углу.
2. Если текущие последние символы двух префиксов совпадают: включить символ в ответ и перейти **по диагонали вверх-влево**.
3. Иначе перейти в соседнюю клетку **вверх** или **влево** с большим значением `V` (при равенстве можно выбрать любую).
4. Остановиться при достижении нулевой строки или столбца.
5. Перевернуть записанные символы: восстановление шло от конца строк к началу.

> [!example] Дополнение — полный учебный пример
> `A = АБВ`, `B = АВБ`. Таблица:
>
> | `A \ B` | ∅ | А | В | Б |
> |---|---:|---:|---:|---:|
> | ∅ | 0 | 0 | 0 | 0 |
> | А | 0 | 1 | 1 | 1 |
> | Б | 0 | 1 | 1 | 2 |
> | В | 0 | 1 | 2 | **2** |
>
> Начало восстановления: `V(3,3)=2`.
> - `В` и `Б` не совпали → можно пойти вверх в `V(2,3)=2`.
> - `Б` и `Б` совпали → записать `Б`, перейти по диагонали к `V(1,2)`.
> - `А` и `В` не совпали → влево к `V(1,1)`.
> - `А` и `А` совпали → записать `А`.
>
> Получили в обратном порядке `БА` → ответ **`АБ`**, длина **2**. Другая допустимая LCS этих строк — **`АВ`**.
>
> ![[../assets/lcs_path.svg|900]]

**Решение может быть не единственным.** В лекции отмечается, что задача обычно требует *хотя бы один* оптимальный вариант, не обязательно все.

### 1.4. Сложность

На каждую пару префиксов вычисляется одна клетка; работа в клетке постоянна:

- Заполнение таблицы: **`O(nm)`**.
- Восстановление одного ответа: **`O(n+m)`**, поскольку при каждом шаге хотя бы один индекс уменьшается.

> [!example] Дополнение — почему DP выгоднее перебора
> Для первой строки длины `n` есть `2^n` способов выбрать/не выбрать её символы. Прямой перебор этих подпоследовательностей требует экспоненциального числа кандидатов. DP вместо этого заполняет только `nm` состояний. При `n=m=20`: `2^20 = 1 048 576` кандидатов против `400` клеток (количество кандидатов и клеток не является точным сравнением машинных операций).

**Упоминание лектора:** термин *псевдополиномиальный алгоритм* будет подробно рассматриваться позднее в связи с динамическим программированием.

> [!warning] Типичные ошибки
> - Путать **подпоследовательность** с **подстрокой** (у подстроки символы подряд).
> - Считать число `V(n,m)` самой подпоследовательностью.
> - При совпадении символов уменьшать только один индекс.
> - При восстановлении принимать скачки, не сохраняя движения вверх **и** влево.

## 2. Точный поиск образца в строке

**Новая задача лекции:** есть *текст* и *образец*. Нужно найти позицию, с которой образец целиком совпадает с непрерывным фрагментом текста.

- **Точный поиск** — все соответствующие символы равны.
- **Приближённый поиск** — разрешены отклонения (например, опечатки); он упомянут, но **в лекции не разбирается**.

### 2.1. Наивный алгоритм

1. Совместить начало образца с первой возможной позицией текста.
2. Сравнивать символы **слева направо** до полного совпадения или первого различия.
3. При различии сдвинуть образец вправо **ровно на один символ** и начать сравнение заново.
4. Проверить все позиции, где образец ещё целиком помещается в тексте.

В худшем случае алгоритм сравнивает почти весь образец при каждой позиции: **`O(nm)`**.

**Плохой пример из идеи лекции:** текст содержит много одинаковых букв `A`, а образец — много `A` и в конце `B`; различие обнаруживается только на последней букве. Программа каждый раз выполняет почти `m` сравнений.

> [!example] Дополнение — небольшой пример
> `Текст = ABABA`, `образец = ABA`.
> 
> - Позиция `0`: `ABA` = `ABA` → найдено.
> - Позиция `1`: `BAB` ≠ `ABA` → пропуск.
> - Позиция `2`: `ABA` = `ABA` → найдено.
> 
> Ответ: индексы **`0`, `2`** (нумерация от нуля). Последняя возможная стартовая позиция равна `n−m`.

**Почему нужны следующие алгоритмы:** сократить количество посимвольных сравнений и/или число рассматриваемых позиций.

## 3. Рабин — Карп: поиск с помощью хешей

### 3.1. Вместо строки сначала сравниваем число

Каждому потенциальному фрагменту текста длины образца ставится в соответствие число — **хеш**. То же делается для образца.

- **Хеши разные:** строки точно разные, проверка символов не нужна.
- **Хеши равны:** *возможно* совпадение; нужно проверить соответствующие символы.

Ситуация «разные строки — одинаковый хеш» называется **коллизией**. Сравнение реальных строк при равенстве хешей гарантирует корректный ответ независимо от коллизий.

### 3.2. Первый вариант: сумма числовых кодов символов

Назначим символам числа и сложим. Главный плюс — новый хеш после сдвига окна получается **удалением ушедшего значения и добавлением пришедшего**:

$$S_{\mathrm{new}}=S_{\mathrm{old}}-a_{\mathrm{out}}+a_{\mathrm{in}}.$$

Но коллизий много: перестановка символов не меняет сумму, и даже разные наборы символов могут давать равные суммы.

### 3.3. Второй вариант: полиномиальный хеш

Чтобы учесть **порядок символов**, числовые коды используют как коэффициенты полинома. Пусть:

- `m` — длина образца;
- `a₁, …, aₘ` — числовые коды символов по порядку;
- `x` — заранее зафиксированное основание.

Тогда:

$$H=a_1x^{m-1}+a_2x^{m-2}+\cdots+a_m.$$

В отличие от суммы, разные позиции получают разные степени `x`.

> [!example] Дополнение — наглядное влияние разрядов
> При `A=1`, `B=2`, `C=3`, `D=4`, `E=5`, `F=6` и `x=10`:
>
> `ABCDE → 12345`, а `BCDEF → 23456`.
>
> **Как получить второй хеш из первого без пересчёта всех букв:**
>
> 1. Удалить первую `A`: `12345 − 10000 = 2345`.
> 2. Сдвинуть все оставшиеся разряды: `2345 × 10 = 23450`.
> 3. Добавить `F`: `23450 + 6 = 23456`.
>
> ![[../assets/rk_rolling.svg|900]]

### 3.4. Скользящий пересчёт полиномиального хеша

Если `a` — числовой код **уходящего первого** символа, `b` — код **приходящего нового** символа, то:

$$\boxed{H_{\mathrm{new}}=(H_{\mathrm{old}}-a x^{m-1})x+b.}$$

Чтение формулы по действиям: **вычесть вклад первого символа → умножить на `x` (сдвинуть разряды) → прибавить новый символ**. Значение `x^(m−1)` рассчитывают заранее.

### 3.5. Ограничение размера чисел: остаток по модулю `d`

Чем длиннее образец, тем больше может быть полиномиальный хеш. Для ограничения размера чисел лектор предлагает хранить **остаток от деления на фиксированное `d`**.

Переход к следующему окну также вычисляется рекуррентно по остаткам.

> [!example] Дополнение — явная формула с модулем
> $$h_{\mathrm{new}}=\bigl((h_{\mathrm{old}}-a x^{m-1})x+b\bigr)\bmod d.$$
> Здесь можно использовать `x^(m−1) mod d`, а промежуточные отрицательные значения нормализовать по модулю.

**Компромисс:** маленькие остатки легче хранить, но разные большие числа могут иметь одинаковый остаток → коллизий становится больше → чаще выполняется посимвольная проверка.

### 3.6. Проверка при совпадении хешей

Это обязательный этап алгоритма:

1. Вычислить хеш образца и первого окна текста.
2. Если хеши совпали — **сравнить сами строки посимвольно**.
3. При полном совпадении записать начальную позицию вхождения.
4. Сдвинуть окно на один символ, пересчитать хеш за постоянное число арифметических операций.
5. Повторять до конца текста.

> [!example] Дополнение — реальная коллизия
> `A=1`, `B=2`, `C=3`, `x=10`, `d=11`, образец `ABC`.
>
> - `ABC → 123 mod 11 = 2`;
> - `CBA → 321 mod 11 = 2`.
>
> Хеши совпали, но уже первые символы `A` и `C` различаются. Это **ложный кандидат**, не найденный образец.

**Сложность:** при редких коллизиях — близко к **`O(n+m)`**; при большом числе совпадающих хешей и длинных проверках — до **`O(nm)`**. Корректность от вероятности коллизий не зависит.

> [!warning] Типичные ошибки
> - Считать равенство хешей доказательством равенства строк.
> - Забывать убрать старший разряд при скользящем пересчёте.
> - Умножать на `x` **до** удаления вклада ушедшего символа.
> - Путать числовой код символа, основание `x` и модуль `d`.

## 4. Бойер — Мур: сравнение справа налево

### 4.1. Идея

Алгоритм похож на наивный поиск, но с двумя принципиальными отличиями:

1. При приложении образца сравнение идёт **с конца образца к началу**.
2. При несовпадении образец обычно сдвигается **больше чем на одну позицию**.

В лекции эти два способа определения перемещения называются **«сдвиг»** (*плохой символ*) и **«прыжок»** (*хороший суффикс*). Для каждого несовпадения оценивается, какой из допустимых сдвигов больше.

### 4.2. Плохой символ

Смотрим на символ текста, **на котором произошло несовпадение**.

- Если такого символа **нет в образце**, часто можно пропустить сразу большой фрагмент текста.
- Если есть, стараемся совместить его с подходящим вхождением **внутри образца**, тем самым пропустив невозможные выравнивания.

**Подготовка в лекции:** рассматривается таблица `t(α)` для символов алфавита. Сначала всем символам присваивается длина образца; затем для встречающихся символов запоминается расстояние от **последнего вхождения** до конца образца. Для последнего символа иногда получается `0`. Лектор отмечает, что **в литературе есть варианты определения таблиц и трактовки последнего символа**.

> [!example] Дополнение — конкретная проверка
> Образец `ABCD`, текст `ZZZZABCD`.
>
> Сравниваем последний `D` с `Z`. `Z` отсутствует в `ABCD`, поэтому сдвигаем образец вправо на **4 позиции**, сразу под `ABCD`.
>
> ![[../assets/bm_shift.svg|900]]

> [!example] Дополнение — уточнение общего правила
> В зависимости от позиции несовпадения расстояние в таблице `t(α)` **не всегда прямо равно окончательному сдвигу образца**. Если несовпадение произошло на позиции `j` (нумерация с 0), можно найти правейшее вхождение плохого символа **строго левее `j`**, на позиции `r`; тогда безопасный сдвиг равен `j−r`. Если такого вхождения нет, принять `r=−1`, сдвиг `j+1`.
>
> Это конкретная реализация правила; в лекции подчёркивается различие между перемещением образца на схеме и переносом указателя в тексте. **Не нужно смешивать величины из разных вариантов таблиц.**

### 4.3. Хороший суффикс («прыжок»)

Если несколько последних символов образца **уже совпали с текстом**, но левее возникло несовпадение, эту информацию можно использовать:

1. Найти подходящее **предыдущее вхождение совпавшего суффикса** в образце.
2. Сдвинуть образец так, чтобы этот фрагмент совместился с уже проверенным текстом.
3. Если полного подходящего повторения нет, может использоваться совпадающая с началом образца часть суффикса.

**Важное замечание лектора:** таблица «прыжков» зависит от **позиции внутри образца**, а не просто от символа. В аудио для одного образца диктуется последовательность значений **`11, 10, 9, 8, 11, 10, 3, 1`**, но точные буквы и расположение элементов на доске по аудио не восстанавливаются однозначно. Преподаватель отдельно говорит, что запоминать программу вычисления прыжков **не требуется**: достаточно понимать идею.

**Примечание о терминологии:** в лекции некоторое время обсуждается, что технически в программе можно говорить не о «движении картинки образца», а о **переносе указателя в тексте**; примеры величин `8`, `10`, `11` относятся к такой трактовке и не обязательно равны геометрическому сдвигу образца.

### 4.4. Сводный алгоритм

1. Приложить образец к очередной позиции текста.
2. Сравнивать **справа налево**.
3. При полном совпадении зафиксировать вхождение.
4. При несовпадении воспользоваться плохим символом и, если применимо, хорошим суффиксом.
5. Выбрать **наибольший безопасный сдвиг** и повторить проверку.

> [!warning] Типичные ошибки
> - Думать, что всегда ждём совпадения **только последней буквы** образца.
> - Считать, что при несовпадении последней буквы сдвиг **всегда** равен длине образца.
> - Использовать формулу `длина образца − число совпавших символов` как универсальный «хороший суффикс» — она неверна.
> - Приравнивать значения таблицы плохих символов к любым указательным прыжкам, не учитывая позицию несовпадения.

## 5. Кнут — Моррис — Пратт (КМП) и конечные автоматы

### 5.1. Зачем вводится конечный автомат

В лекции КМП объясняется **через конечный автомат**, прежде чем перейти к очередной теме теории автоматов.

У конечного автомата есть:

- **множество состояний**;
- **входной алфавит**;
- **выходной алфавит**;
- правила, задающие **новое состояние и выходное действие** по текущему состоянию и входному символу.

Каждый такт: **состояние + вход → новое состояние + выход**. В лекции приведён бытовой пример автомата продажи кофе/шоколада: ожидание, нажатие кнопки, оплата, выдача товара.

### 5.2. Состояния при поиске образца

В лекции разбирается образец вида `АБАБСБ` (ниже тот же образец записан латиницей: `ABABCB`).

**Состояние `j`** означает: последние `j` прочитанных символов текста совпадают с **первыми `j` символами образца** (и это максимально подходящий текущий префикс).

| Состояние | Уже совпавшее начало образца | Следующий ожидаемый символ |
|---|---|---|
| `0` | ничего | `A` |
| `1` | `A` | `B` |
| `2` | `AB` | `A` |
| `3` | `ABA` | `B` |
| `4` | `ABAB` | `C` |
| `5` | `ABABC` | `B` |
| `6` | `ABABCB` | образец найден |

При совпадении ожидаемого символа происходит переход `j → j+1`.

### 5.3. Что делать при несовпадении

Главная идея КМП: **не начинать сравнение с нуля, если часть уже прочитанного текста подходит под начало образца**.

Например, совпало `ABAB` (состояние `4`), но вместо ожидаемой `C` пришла `A`.

Уже совпавшее `ABAB`:

- начинается с `AB`;
- заканчивается на `AB`.

Можно **сохранить два известных совпадения** и перейти из состояния `4` в состояние `2`. **Текущую новую букву `A` ещё не обработали**: её снова сравнивают, теперь с третьей буквой образца. Она подходит → переход `2 → 3`.

**Смысл:** новая попытка поиска начинается правее, но начальные `AB` уже были проверены в старом положении. Никаких пропусков букв *внутри* предполагаемой подстроки нет. Указатель по тексту **не возвращается назад**.

> [!example] Дополнение — диаграмма двух указателей и перехода
> ![[../assets/kmp_fallback.svg|900]]
> Здесь `i` — позиция очередного символа текста, `j` — состояние автомата. При откате `j` изменяется, а `i` остаётся на текущей букве до её обработки.

### 5.4. Как работает поиск целиком

1. Один раз подготовить автомат переходов **по самому образцу**.
2. Читать текст **слева направо**.
3. При совпадении с ожидаемым символом перейти в следующее состояние.
4. При несовпадении перейти в состояние, где сохраняется максимально длинное подходящее окончание ранее совпавшего текста, и обработать **тот же** символ.
5. Если состояние достигло длины образца, **образец найден**; сохранить позицию начала вхождения.

> [!example] Дополнение — полный короткий прогон
> Ищем `ABABCB` в тексте `ABABABCB` (индексы `0…7`).
>
> | Индекс текста | Буква | Состояние после обработки |
> |---:|:---:|:---|
> | 0 | A | 1 |
> | 1 | B | 2 |
> | 2 | A | 3 |
> | 3 | B | 4 |
> | 4 | A | `4 → 2 → 3` |
> | 5 | B | 4 |
> | 6 | C | 5 |
> | 7 | B | 6 — найдено |
>
> Позиция начала: `7 − 6 + 1 = 2`.

> [!example] Дополнение — связь с префикс-функцией
> Реализацию КМП часто записывают через массив **префикс-функции** `pi`. Для образца `ABABCB` он равен `[0, 0, 1, 2, 0, 0]`.
>
> Значение `pi[k]` — длина наибольшего *собственного* префикса части образца, заканчивающейся на позиции `k`, который одновременно является её суффиксом. В частности, `pi[3]=2` для `ABAB`.
>
> При несовпадении после состояния `j=4` делают `j=pi[3]=2`, **не меняя позицию текста**. Подробная реализация `pi` на лекции не рассматривается; это альтернативное программное представление той же идеи.

**Сложность (дополнение):** при стандартном вычислении переходов/префикс-функции подготовка `O(m)`, поиск `O(n)`, суммарно **`O(n+m)`**. Эту оценку следует отличать от размера явно заданной полной таблицы переходов по всему алфавиту.

> [!warning] Типичные ошибки
> - Думать, что «откат состояния» означает возврат назад по тексту.
> - Искать просто **любой** повторяющийся кусок, а не окончание совпавшей части, являющееся также началом образца.
> - После отката сразу пропускать букву, которая вызвала несовпадение: её ещё нужно обработать.
> - Считать, что алгоритм разрешает пропуски внутри найденной **подстроки** — это по-прежнему точный поиск.

## 6. Новая глава: кодирование и защита информации

В конце лекции начинается новая глава. Рассматриваются три задачи кодирования:

1. **Сжатие информации** — уменьшить объём представления.
2. **Защита от ошибок** — обнаруживать/исправлять искажения из-за сбоев или передачи.
3. **Шифрование** — защита от постороннего доступа.

Здесь начинается обсуждение **сжатия**.

### 6.1. Задача оптимального префиксного кодирования

Каждому символу исходного алфавита сопоставляется **двоичное кодовое слово переменной длины**.

- `pᵢ` — вероятность (или относительная частота) символа `i`;
- `sᵢ` — длина его двоичного кода;
- `n` — количество кодируемых символов.

Нужно минимизировать **среднюю длину**:

$$\boxed{L=\sum_{i=1}^{n} p_i s_i\longrightarrow\min.}$$

Идея: **частые символы получают короткие коды**, редкие могут получать длинные.

**Префиксный код:** ни одно кодовое слово не является началом другого. Благодаря этому поток нулей и единиц можно декодировать **без разделителей**: как только встречено полное кодовое слово, его можно вывести и продолжить чтение.

В лекции эта задача связывается с **неравенством Крафта** и двоичным деревом: кодовые слова находятся в **листьях**, а не посередине пути к другим словам.

> [!example] Дополнение — точная форма неравенства Крафта
> Для длин двоичного префиксного кода обязательно
>
> $$\sum_{i=1}^{n}2^{-s_i}\le 1.$$
>
> Более того, если набор положительных целых длин удовлетворяет неравенству, префиксный код с такими длинами существует. Сами кодовые слова при этом ещё нужно построить.

### 6.2. Построение алгоритма Хаффмана

**Алгоритм из лекции:**

1. Выбрать **два символа с наименьшими вероятностями**.
2. Объединить их в новый составной символ; его вероятность равна **сумме** исходных.
3. Повторять объединения двух минимальных вероятностей, сохраняя историю объединений, пока не получится одно дерево (в лекции сначала сводят список к двум элементам, затем соединяют их корнем).
4. Назначить каждому ветвлению `0` и `1`.
5. Код исходного символа — последовательность битов на пути **от корня к соответствующему листу**.

**Что получается:** корректный префиксный код с переменной длиной. При распаковке нужно знать **таблицу кодов или само дерево**; без этой информации декодировать поток нельзя.

> [!example] Дополнение — пример объединений
> Пусть частоты: `A=0.4`, `B=0.3`, `C=0.2`, `D=0.1`.
>
> - `C + D = 0.3`;
> - `B + (CD) = 0.6`;
> - `A + (BCD) = 1.0`.
>
> Один из возможных кодов: `A→0`, `B→10`, `C→110`, `D→111`.
>
> Средняя длина: `0.4·1 + 0.3·2 + 0.2·3 + 0.1·3 = 1.9` бита на символ.

### 6.3. Ограничения посимвольного Хаффмана

Лектор подчёркивает: если кодировать **отдельные символы**, алгоритм учитывает их **частоты**, но не учитывает устойчивые сочетания букв, слоги и повторяющиеся пары/тройки как самостоятельные объекты.

Поэтому Хаффман может применяться **в сочетании с другими способами преобразования или сжатия**. В лекции отдельно отмечается, что кодируемыми объектами могут быть не только буквы естественного языка.

> [!example] Дополнение — иллюстрация ограничения
> Для `ABABABAB` посимвольный Хаффман рассматривает отдельные `A` и `B`, но сам не выделяет повторяющийся блок `AB`. Блочное кодирование возможно при **изменении исходного алфавита/единицы кодирования**, но это уже другая постановка задачи.

**Граница данной лекции:** доказательство оптимальности Хаффмана **объявлено темой следующего занятия**. Три леммы, их доказательства и Зив — Лемпель в эту аудиолекцию не входят; здесь не добавляются как якобы её материал.

## 7. Краткая шпаргалка

*Дополнение: сводная таблица по материалу лекции; асимптотические оценки там, где они не названы явно в записи, приведены для ориентира.*

| Алгоритм | Что ищет / делает | Ключевой приём | Сложность / особенность |
|---|---|---|---|
| **LCS (DP)** | Общая *подпоследовательность* | Таблица для пар префиксов + обратный проход | `O(nm)` |
| **Наивный поиск** | Точное вхождение *подстроки* | Посимвольная проверка с каждой позиции | `O(nm)` в худшем случае |
| **Рабин — Карп** | Точную подстроку | Скользящий хеш, подтверждение при равенстве | Обычно близко к `O(n+m)`, худшее `O(nm)` |
| **Бойер — Мур** | Точную подстроку | Справа налево; плохой символ / хороший суффикс | Пропускает многие выравнивания; оценка зависит от варианта |
| **КМП** | Точную подстроку | Состояния и переходы без отката указателя текста | `O(n+m)` в стандартной реализации |
| **Хаффман** | Префиксный код малой средней длины | Объединение двух минимальных вероятностей | Нужны частоты и дерево/таблица кодов |

### Быстрые алгоритмы действий

**LCS:** заполнить таблицу → взять значение в правом нижнем углу → пройти назад по совпадениям и большим соседям → перевернуть собранные символы.

**Рабин — Карп:** хеш образца → хеш окна → сравнить числа → при равенстве проверить символы → пересчитать хеш при сдвиге.

**Бойер — Мур:** сравнение с конца → несовпадение → оценить плохой символ и хороший суффикс → безопасный сдвиг → повторить.

**КМП:** подготовить переходы → читать текст один раз слева направо → при несовпадении сохранить подходящий префикс через откат состояния → полное совпадение означает найденное вхождение.

**Хаффман:** две минимальные вероятности → объединить → повторить → назначить `0/1` рёбрам → читать код от корня к листу.

## Приложение. Учебный код

> [!example] Дополнение
> В аудиолекции не приводятся готовые Python-реализации этих алгоритмов. Код ниже добавлен **только как иллюстрация вычислений**, не как обязательный материал преподавателя. Алгоритмы Бойера — Мура и КМП в данном конспекте оставлены на уровне логики, соответствующем занятию.

### A. LCS: длина и одна оптимальная подпоследовательность

```python

def lcs(a: str, b: str) -> tuple[int, str]:
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    i, j = n, m
    result = []
    while i > 0 and j > 0:
        if a[i - 1] == b[j - 1]:
            result.append(a[i - 1])
            i -= 1
            j -= 1
        elif dp[i - 1][j] >= dp[i][j - 1]:
            i -= 1
        else:
            j -= 1

    return dp[n][m], ''.join(reversed(result))


print(lcs('АБВ', 'АВБ'))  # (2, 'АБ')
```

**Зачем дополнительные нулевые строка и столбец?** Для сравнения с пустым префиксом. Обращение `a[i-1]` связано с индексацией Python **с нуля**, а не с математической идеей `i−1,j−1` при совпадении.

### B. Рабин — Карп: проверка реальных строк после хеша

```python

def rabin_karp(text: str, pattern: str) -> list[int]:
    n, m = len(text), len(pattern)
    if m == 0 or m > n:
        return []

    # Учебная версия: только заглавные латинские буквы A–Z.
    def code(ch: str) -> int:
        return ord(ch) - ord('A') + 1

    x, mod = 10, 11  # Небольшой модуль специально показывает коллизии.
    target_hash = current_hash = 0

    for i in range(m):
        target_hash = (target_hash * x + code(pattern[i])) % mod
        current_hash = (current_hash * x + code(text[i])) % mod

    power = pow(x, m - 1, mod)
    positions = []

    for start in range(n - m + 1):
        # Совпадение хешей — лишь повод проверить сами символы.
        if current_hash == target_hash:
            if text[start:start + m] == pattern:
                positions.append(start)

        if start < n - m:
            outgoing = code(text[start])
            incoming = code(text[start + m])
            current_hash = ((current_hash - outgoing * power) * x
                            + incoming) % mod

    return positions


print(rabin_karp('ABCBA', 'ABC'))  # [0]
```

**Проверка корректности:** даже если `ABC` и `CBA` имеют одинаковый остаток при делении на `11`, второй фрагмент **не принимается**, поскольку реальная строка отличается от образца.
