3. new / delete с объектами

malloc только выделяет сырые байты памяти и не вызывает конструктор.

free освобождает память, но не вызывает деструктор.

new:

  1. выделяет память;
  2. вызывает конструктор Server(5432).

delete:

  1. вызывает деструктор;
  2. освобождает память.

Если указатель исчезнет без delete:

сам s уничтожится, но объект в куче останется → утечка памяти.

4. Placement new

Placement new позволяет создать объект в уже выделенной памяти.

Placement new не выделяет память, а только вызывает конструктор по указанному адресу.

Уничтожение:

После malloc + placement new нельзя использовать обычный delete.

Placement new обычно нужен при реализации структур данных вроде std::vector.

5. new[] / delete[] с объектами

new[] вызывает конструктор по умолчанию для каждого элемента массива.

delete[] вызывает деструктор каждого объекта.

Если у класса нет конструктора без аргументов, new BigInt[100] не скомпилируется.

8. Виды умных указателей

scoped_ptr

  • нельзя копировать;
  • нельзя передавать владение;
  • один владелец.

unique_ptr

  • нельзя копировать;
  • можно перемещать;
  • можно передавать владение;
  • в каждый момент владелец один.

shared_ptr

  • можно копировать;
  • несколько указателей могут владеть одним объектом.

9. shared_ptr

Основная идея — счётчик владельцев.

При refcount == 0 удаляется сам объект.

Счётчик должен быть общим для всех копий.

Циклические ссылки

Объекты удерживают друг друга, поэтому счётчики не доходят до нуля.

Для разрыва таких циклов используется weak_ptr, который не увеличивает счётчик владения.

14. Виртуальный деструктор

Проблема:

Если деструктор Button обычный, правильный деструктор ColoredButton может не быть вызван.

Поэтому:

Теперь при delete по Button* вызывается деструктор реального объекта, а затем деструктор базового класса.

Если в классе есть виртуальные методы, деструктор обычно тоже должен быть virtual.

Если деструктор базового класса виртуальный, деструкторы наследников автоматически тоже виртуальные.

Уровни доступа

15. public, protected, private

protected позволяет наследнику использовать детали реализации базового класса, не открывая их внешнему коду.

Иногда вместо protected поля лучше оставить поле private и дать метод доступа, например getCaption().

16. Виды наследования

public

Это отношение «B является A».

protected

public члены базового класса становятся protected.

private

Все неприватные члены базового класса становятся private.

При protected/private наследовании внешний код не может обычным образом сделать Derived* -> Base*.

Не-public наследование используется редко; часто вместо него лучше композиция.

class и struct

В C++ они почти одинаковые: оба могут иметь методы, конструкторы, деструкторы, наследование, virtual и уровни доступа.
