Лекция 11 — Хаффман, LZ, суффиксы и BWT

16 нояб. 2026 г.время чтения ~11 мин.

Дискретная математика — Хаффман, Зив — Лемпель, суффиксные деревья, BWT

← К лекциям

Главное за минуту

  • Хаффман: часто встречающимся символам — короткие коды; два самых редких объединяются.
  • Зив — Лемпель (LZ78): повторяющиеся фрагменты заменяются ссылками на словарь и новым символом.
  • Суффиксное дерево: хранит все окончания строки, чтобы быстро находить подстроки.
  • Барроуз — Уилер (BWT): обратимо переставляет символы, часто собирая одинаковые рядом; сам по себе не сжимает.

Порядок конспекта: три леммы Хаффмана → словарный алгоритм Зива — Лемпеля → суффиксное дерево → прямое и обратное BWT. Учебные примеры, не приведённые непосредственно в лекции, помечены как дополнение.

1. Оптимальность алгоритма Хаффмана

Обозначения

Есть n≥2 символов. Для каждого символа с номером i:

  • pi​>0 — вероятность появления;
  • si​ — длина его двоичного кодового слова;
  • P=(p1​,…,pn​) — набор вероятностей;
  • S=(s1​,…,sn​) — набор длин.

Вероятности упорядочены:

p1​≥p2​≥…≥pn​,i=1∑n​pi​=1.

Средняя длина кодирования одного символа:

L=i=1∑n​pi​si​⟶min.​

Префиксный код: ни одно кодовое слово не является началом другого. Это позволяет декодировать поток без дополнительных разделителей.

Лемма 1. Более вероятному символу — не более длинный код

Формулировка. Существует оптимальный префиксный код, в котором

s1​≤s2​≤…≤sn​.​

Доказательство от противного. Пусть для двух символов i и j выполнено pi​>pj​, но si​>sj​: частому символу достался более длинный код. Поменяем их кодовые слова местами.

  • Префиксность сохраняется: набор двоичных слов не меняется, меняются лишь соответствия «слово ↔ символ».
  • Разность средних длин до и после перестановки:
L1​−L2​=(pi​−pj​)(si​−sj​)>0.

Средняя длина уменьшилась, хотя код был оптимальным. Противоречие. При равных вероятностях перестановка не влияет на среднюю длину, поэтому нужный порядок длин также можно обеспечить. □

Лемма 2. Два последних кода одинаковой длины

Формулировка. Для оптимального кода с упорядоченными длинами можно добиться

sn−1​=sn​.​

Доказательство от противного (короткий способ). Предположим sn−1​<sn​. Тогда последний код — единственный самый длинный. Удалим у него последний бит.

Почему префиксность сохранится?

  1. Если какой-то другой код был бы префиксом укороченного слова, он уже был бы префиксом исходного слова — невозможно.
  2. Укороченное слово не может быть префиксом другого кода: длины всех остальных слов не больше sn−1​≤sn​−1; совпадение также невозможно по пункту 1.

Получился корректный код с меньшей средней длиной (на pn​>0). Противоречие оптимальности. Значит, sn−1​=sn​. □

Что лемма 2 ещё не утверждает

Равенство длин само по себе не означает, что эти два слова — соседние листья дерева. Для шага Хаффмана дополнительно используют свойство оптимального дерева: два самых редких символа можно расположить в двух самых глубоких листьях с общим родителем.

Лемма 3. Объединение двух наименее вероятных символов

Положим

p′=pn−1​+pn​.​

Объединяем два самых редких символа в один временный символ с вероятностью p′. Получается задача для n−1 символов.

Формулировка. Если Ln∗​ — минимальная средняя длина для исходных n символов, а Ln−1∗​ — минимальная средняя длина после объединения, то

Ln∗​=Ln−1∗​+p′.​

Почему два символа можно объединить. В оптимальном дереве не бывает внутреннего узла с одним ребёнком: такой узел можно убрать и укоротить код. Поэтому у одного из листьев максимальной глубины есть соседний лист с тем же родителем. По лемме 1 метки символов можно переставить так, чтобы в этих двух листьях стояли самые редкие символы, не увеличивая среднюю длину.

Доказательство оптимальности объединения (от противного):

  1. Возьмём оптимальное дерево исходной задачи. Два самых редких символа расположены в соседних листьях. Сольём их в одного родителя — допустимое дерево для сокращённой задачи.
  2. Обратное действие — разделение объединённого символа на два листа — увеличивает длину кода каждого из этих двух символов на 1. Поэтому средняя длина увеличивается ровно на pn−1​+pn​=p′.
  3. Предположим, что сокращённое дерево было неоптимальным. Тогда существует более короткий в среднем код для n−1 символов. Разделим в нём объединённый символ на два: добавится то же число p′.
  4. Получим код для исходных символов лучше исходного оптимального. Противоречие.

Следовательно, оптимальный код для сокращённой задачи действительно позволяет получить оптимальный код для исходной. □

Алгоритм Хаффмана — кратко

  1. Создать по листу на каждый символ с его вероятностью.
  2. Выбрать два узла с наименьшими вероятностями.
  3. Объединить их в нового родителя с суммой вероятностей; рёбра пометить 0 и 1.
  4. Повторять, пока не останется один корень.
  5. Код символа — последовательность 0/1 по пути от корня до его листа.

Дополнение — пример. При вероятностях A: 0,5, B: 0,25, C: 0,125, D: 0,125 можно получить:

СимволКодДлина
A01
B102
C1103
D1113

Средняя длина: L=0,5⋅1+0,25⋅2+0,125⋅3+0,125⋅3=1,75 бит/символ.

2. Алгоритм Зива — Лемпеля: словарный вариант LZ78

Идея

Вместо записи фрагмента целиком используем номер уже известного фрагмента + один новый символ.

Словарь пополняется прямо по мере чтения текста. Запись 0 обозначает пустую строку.

Если словарь[3] = ab, то запись 3d означает abd.

Кодирование — алгоритм

  1. Идём по тексту слева направо.
  2. На текущем месте находим самый длинный фрагмент, который уже есть в словаре и совпадает с началом оставшегося текста.
  3. Берём следующий за ним символ c; если совпадения нет, используем пустой фрагмент № 0.
  4. Выводим пару (номер, c) и добавляем новый фрагмент в словарь.
  5. Продолжаем с первого ещё не обработанного символа.

Важно

Ищем не самый длинный элемент всего словаря, а самый длинный подходящий префикс оставшегося текста.

Пример словарного кодирования из лекции

Здесь используются символы a, b, d и конечный маркер %.

№ нового фрагментаФрагментКодКак получен

2b0bпустой + b

4ba2a№ 2 b + a
5bb2b№ 2 b + b

Кодовая последовательность:

Исходная строка получается конкатенацией фрагментов:

Распаковка LZ78

Декодер изначально знает только запись № 0 (пустую строку). Читает пары по порядку, восстанавливает каждую как словарь[номер] + символ и добавляет результат в словарь под следующим номером.

Например: 0a | 0b | 1b | 3a → a | b | ab | aba → abababa.

Почему исходный словарь передавать не требуется? Декодер создаёт его в том же порядке, что и кодировщик.

Дополнение: LZ77 и отличие от LZ78

В LZ77 повтор обычно задаётся ссылкой назад (расстояние, длина) на ранее обработанный текст; в LZ78 используются номера фрагментов словаря. Например, в ABCDEFABC второе ABC можно представить ссылкой LZ77 (6, 3), если расстояние измеряется назад от начала повтора. Суффиксные структуры могут ускорять поиск совпадений в LZ77, но не обязательны.

3. Суффиксный бор и суффиксное дерево

Определения

  • Суффикс строки — её окончание, начинающееся с некоторой позиции и продолжающееся до конца.
  • Подстрока — непрерывный фрагмент, который может находиться и в середине текста.
  • Суффиксный бор (suffix trie) — дерево всех суффиксов с отдельным символом на каждом ребре.
  • Суффиксное дерево — сжатый бор: цепочки рёбер без развилок объединены в одно ребро с подстрокой.

Добавляется специальный завершающий символ $ (или %), отсутствующий в исходном тексте. Это позволяет явно отделять окончания суффиксов.

Построение на строке аба$ — дополнение

Позиция началаСуффикс
1аба$
2ба$
3а$
4$

Как читать рисунок:

  • Путь а → ба$ приводит к листу 1: суффикс аба$.
  • Путь а → $ приводит к листу 3: суффикс а$.
  • Путь ба$ приводит к листу 2.
  • Путь $ приводит к листу 4.

Суффикса б нет: буква б не является окончанием строки аба. Но есть суффикс ба (или ба$ с маркером).

Построение дерева — алгоритм

  1. Добавить к исходной строке уникальный символ конца.
  2. Рассмотреть все суффиксы: с первой позиции, со второй и так далее.
  3. Добавлять каждый суффикс из корня. Совпадающие начальные части используют уже существующий путь; в месте первого различия появляется развилка.
  4. Сжать неразветвляющиеся цепочки в рёбра с целыми подстроками.
  5. В листьях хранить позиции начала суффиксов.

Пример из лекции: Карл_у_Клары_украл_кораллы%, где _ обозначает пробел, % — конец текста. Сначала по алфавиту выделяются разные первые символы суффиксов; затем ветви дробятся по следующим буквам. Большое дерево на рисунке в лекции показывает этот же принцип.

Для чего дерево нужно?

Пусть текст banana$, а ищем ana. Эта подстрока встречается на позициях 2 и 4, потому что суффиксы с этих позиций начинаются на ana:

Поэтому достаточно пройти из корня по a → n → a (в сжатом дереве несколько символов могут лежать на одном ребре). Если путь есть, подстрока встречается. Номера листьев под достигнутым узлом дают все позиции вхождений.

Для LZ77: вместо заранее заданного образца ищут самое длинное начало необработанного текста, совпадающее с ранее обработанным фрагментом. Это не поиск самой длинной ветви дерева вообще.

Дополнение о сложности

Наивное добавление всех суффиксов может занимать O(n2) времени; суффиксное дерево имеет O(n) узлов и рёбер (при сжатых рёбрах и уникальном терминаторе). Специальные алгоритмы позволяют построить его за линейное время при подходящих предпосылках. Поиск заданной подстроки длины m — O(m), перечисление k вхождений — дополнительно O(k).

4. Преобразование Барроуза — Уилера (BWT)

Зачем оно нужно?

BWT не уменьшает размер текста само по себе. Оно обратимо переставляет символы так, что в типичных текстах одинаковые символы часто собираются в группы. Это удобно для последующего сжатия (например, кодирования серий повторений).

Прямое BWT — пример аба$ (дополнение)

Шаг 1. Выписать все циклические сдвиги: каждый раз перенести первый символ в конец. $ — обычная карточка при перестановке, не команда остановиться.

Шаг 2. Отсортировать строки целиком лексикографически, считая $ < а < б:

Отсортированная строкаПоследний символ
$абаа
а$абб
аба$$
ба$аа

Сортировка меняет порядок строк, но не переставляет буквы внутри них. Например, а$аб раньше аба$, потому что второй символ $ меньше б.

Шаг 3. Собрать последний столбец сверху вниз: аба$ → аб$а.

Почему сортировка полезна? Строки с общими началами оказываются рядом; их предшествующие символы часто совпадают. Именно предшествующие символы записаны в последнем столбце.

Обратное BWT — как из аб$а вернуть аба$

Дано: L = аб$а — последний столбец отсортированной таблицы. Нужно восстановить все циклические сдвиги.

Алгоритм:

  1. Создать 4 пустые строки (по числу символов в L).
  2. Приписать слева к строкам символы L по порядку: а, б, $, а.
  3. Отсортировать полученные строки.
  4. Снова приписать те же символы L слева, по одному на строку, в текущем отсортированном порядке. Снова отсортировать.
  5. Повторять, пока каждая строка не будет иметь длину 4.
  6. Выбрать строку, заканчивающуюся на $: это исходная строка.

Что означает столбец «Было»? Это отсортированные строки прошлого шага — не новый текст и не новая информация извне.

Переход от шага 1 к шагу 2:

Из LБыло после шага 1Приписываем слева
а$а$
баба
$а$а
абаб

После сортировки: $а, а$, аб, ба.

Полная таблица — результат после каждой сортировки:

ШагСтроки
1$, а, а, б
2$а, а$, аб, ба
3$аб, а$а, аба, ба$
4$аба, а$аб, аба$, ба$а

Почему работает? В циклическом сдвиге последний символ находится непосредственно перед первым, если читать исходную строку по кругу. Приписывание слева восстанавливает ещё один символ перед уже известным началом; сортировка возвращает правильный порядок строк для следующего прохода.

Итог: аб$а → аба$, исходный текст восстановлен без потерь.

5. Алгоритмы: мини-шпаргалка

ТемаАлгоритм в одну строку
ХаффманДва минимальных веса → объединить → повторять → прочитать коды по дереву
LZ78Самый длинный известный префикс → плюс новый символ → записать (номер, символ)
LZ78, распаковкасловарь[номер] + символ → вывести → занести в словарь
Суффиксное деревоВсе суффиксы → общий путь для общих начал → сжать цепочки
Поиск в деревеПройти путь по символам образца → позиции в листьях
Прямое BWTЦиклические сдвиги → сортировка строк → последний столбец
Обратное BWTПриписать L слева → сортировать → повторять → строка с $ в конце

Типичные ошибки

  • Хаффман: путать частоту с длиной, полагать, что равная глубина листьев уже означает общего родителя.
  • LZ78: искать самый длинный фрагмент всего словаря, не проверяя совпадение с оставшимся текстом; путать номер фрагмента с расстоянием назад из LZ77.
  • Суффиксы: считать любую подстроку суффиксом; путать суффиксный бор и сжатое суффиксное дерево.
  • BWT: сортировать символы внутри строк, а не строки целиком; считать $ командой остановки при циклическом сдвиге; принимать BWT за уже сжатый текст.
  • Обратное BWT: приписывать справа вместо слева; менять L на каждом шаге; использовать неотсортированные строки предыдущего шага.
